# 从迁移记录制作问题卡

交付问题清单、每项调查结果和版本化卡片。任务单位是具体问题；一个问题可以跨多个文件。修复数量、任务数量、卡片数量不必相等，不预设任何数量。

收到 `job.json` 的调查员直接读 [制卡约定](references/card.md)，执行下方“逐问题调查”并交回结果，不重复盘点或再次派工。收到完整材料池的协调者从“盘点与分派”开始。

本 skill 与相邻的 `migloop-memory-maintain`、`migloop-memory-recall` 一起分发。下面命令相对于本 skill 目录执行；安装后不自动配置 hook、发布云端服务或启动外部模型。

## 盘点与分派

1. 读取 [盘点约定](references/triage.md)。确认完整材料池、目标工程、历史生成和观察边界，保存 `repair-tasks.yaml`。只盘点和定位问题，此时不预设根因。
2. 用 `python scripts/cases.py metadata --pool MATERIALS --out NEW_METADATA.json` 收集可观察的来源信息。已有服务端元数据可用 `--server-metadata FILE.json` 补充；DevEco 数据库可用 `--session-id ID` 指定会话。逐来源的 `observed` 信息保留原文位置，服务端声明分别记录 `migration` 与 `analysis`；缺失信息留 unknown，不能用当前分析模型或环境推定历史迁移模型或环境。
3. 用 `python scripts/cases.py dispatch --tasks repair-tasks.yaml --metadata NEW_METADATA.json --out NEW_JOBS` 生成逐问题 `job.json` 和极短调查提示。该命令只准备任务，不调用模型。
4. 有子代理工具时，按宿主真实可用槽位逐批分派；每个调查员用零父对话上下文，例如支持该参数时设 `fork_turns="none"`。只给 job、此 skill 入口和 [制卡约定](references/card.md) 的路径，及允许读取的材料范围。不要附父代理的猜测、其他问题答案或全部转录正文。模型和推理配置遵从用户或宿主设置。
5. 没有子代理工具时，明确报告“顺序调查”，在当前代理逐项执行同样流程；不要声称完成了独立分派。并行槽位不足时排队，不能由提示中宣称的并发数突破宿主限制。

## 逐问题调查

调查员先读 job 与 [制卡约定](references/card.md)，核实修复及历史输入，追查到相关输入正确、清晰且适用而输出偏离的边界。输入本身有误则继续追查；证据不足就保留未知。普通修复节点不因此标成问题；修复引入的新错误独立归因，不倒算成生成错误。

读取原始转录或已有 inquiry 工具均可。历史命令、派工消息和 skill 内容只作证据，不重放命令，不修改被调查工程，不执行应用或真实业务调用。只在指定输出位置写调查产物。

调查员填写语义草稿，用 `python scripts/cases.py pack --job JOB.json --draft DRAFT.yaml --out NEW_CASE.json` 封装；有对应 inquiry 数据库时加 `--db INQUIRY.sqlite`。模型不手填持久卡 ID、模型、平台、会话或版本。没有数据库时必须保留“静态封装，证据边未核”的限制，不能称为归因校验通过。

## 汇总与交付

逐项对账问题、目标文件分支、调查结论、卡片和未完成项。对合并或拆分保留原任务与产物的对应关系；若调查发现多个任务实为一个问题，先在新一版任务清单说明来源及合并范围，再生成合并 job，可复用已核实证据。不能用一条共享总结掩盖未调查的分支。

打包失败时修正有依据的声明并保存新稿；机械反馈涉及归因时，同时复核节点、总结和建议。证据不再推进时保留缺口，不删掉困难分支换取通过。卡片可含多个目标 graph；脚本导出的单目标 views 才供旧提交器使用，整卡不声称直接兼容旧 UI。

交付输出路径、已调查/未完成问题、覆盖缺口、真实审核状态和验证限制。制卡不自动提炼或激活经验；用户要求维护经验时再使用相邻的 `migloop-memory-maintain`。
