# 按任务召回经验

输入是当前任务及经验包的 `index.md` 路径。用正常的文件读取能力查经验，不需要专用 MCP 或查询脚本。

这些经验来自真实迁移中的失败与修复，其中一些问题在规格生成、代码实现、收敛检查或编译通过后仍然存在，直到后续运行或视觉验证才暴露。它们用于提醒容易漏掉的具体失效模式。与当前任务相关且适用条件成立时，应将对应做法落实到方案或实现中，而不只是记录“已读”；已有实现已覆盖时无需重复工作。经验补充当前源码和规格，不替代对它们的理解。

提醒时机由 hook／宿主配置决定；本 skill 只说明被唤起后如何按需使用经验，不另行规定启动或写前提醒流程。结合当前任务和已有输入选择相关经验，复用同一版本下已读内容；没有新相关项就继续原任务。

本 skill 可单独发布；附带的旧库诊断脚本与 hook 安装脚本只依赖 Python，不需要其他 skill 或 inquiry 内核。正常召回只读指引和相关经验，不加载脚本源码或历史转录。

1. **写下三个线索。** 当前任务的阶段（spec 规格提取 / plan 计划与派工 / execute 执行与实现 / verify 验证与判读；repair 修复、converge 收敛与移交为补充值）、输入里出现的符号（API、组件、装饰器、文件名）和领域猜测（app / arkts / data / ui / process）。
2. **按线索取候选。** 根 `index.md` 旁的 `catalog.jsonl` 每行一条经验（id、summary、topic、stage、signals、path），`signals.json` 把符号映射到经验 id；用 grep 或按字段过滤得到候选。也可从根索引的领域或阶段入口浏览：`topics/` 下每个索引只列下一层，`by-stage/` 按阶段列出同领域主题下的经验。
3. **选经验。** 按当前要作的决策核对候选的 summary 和 signals，再按 catalog 的 path 打开 `topics/<主题>/<id>.lesson.md` 看时机、情境和例外，不按历史项目名匹配；通常读 3 到 5 条，跳过已能排除的条目。
4. **用于当前任务。** 已有源码、规格足以判断条件时，直接采用适用做法；关键前提不明时，只补充足以确定该前提的局部材料。当前方案已符合时继续，不为体现采用而改动。“可选检查”是按需的额外验证，不因读到经验另起验证流程，项目原有必需测试照常执行；旧包标题为“检查”的条目也按此理解。不用遍历整棵树或列出无关条目的跳过理由。

符号已明确时直接查 `signals.json`；线索都不明确时再搜索 catalog 的 summary 或经验正文。经验正文末尾的「同源经验」列出由相同来源卡提炼的其他经验，顺手核对即可，不必展开。任务或输入明显变化后再补查，可复用同一版本下已读的经验。

经验是有条件的历史建议。当前材料与经验冲突时核实条件，再决定采用、调整或暂缓；历史样例的数值和局部修法不自动覆盖当前要求。按需读取并用于原任务即可，无需额外标记已读、列出经验 ID/版本或提交引用、采用清单。

部署阅读包只保留来源计数，不提供完整来源列表；计数反映历史样本覆盖，不是正确概率或成功复用次数，适用条件优先。正常召回不用寻找卡片或读取manifest。若当前任务明确需要复核且开发环境提供了来源卡，再一起看其结论与unknown，区分已观察事实与新推断。发布版本、来源复核及旧 store 入口见 [使用约定](references/usage.md)，遇到这些情况再读。维护者接入 Claude Code 写前提醒见 [宿主接入](references/claude-hook.md)；普通召回不需要读安装说明。
