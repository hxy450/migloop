# 返修调查内核：冻结实现约定

状态：2026-09-11 开始实现。分支 `dev/inquiry-core`，旧基线 `b7061d2`。这份约定不是收益已达标的声明。

当前进度：独立内核/MCP/最小页面已实现，i07冻结前93项工程回归通过；没有切换旧默认入口。Luna i05完整十文件核心20/28，仍有重大额外错误，收益验收未通过；后续轮次见 [实验目录](../experiments/inquiry-20260911/)。第一版记录仅代表当时状态。

## 1. 交付与退出条件

围绕一个被修文件，自由查询生成与修复历史，解释修改，并把带原始证据的结论挂到文件/agent节点上。正确性、可审计性优先于成本。

新内核位于 `migloop.inquiry`，**不得导入旧 atoms、filestory、probe、verdict、service 或调用旧 MCP**。原 migloop 的其他功能、适配器、历史产物保持不动。新内核验收之前不切换现有默认页面；验收后才决定旧返修代码的退役范围，不能永久维护两套新功能。

第一版必须完成：持久化事件索引、时间查询、完整原文可达、批量查询、原生读写关系、候选入口、结构化结论校验、最低限度的页面展示。仅要求现有 Claude/Codex 转录协议。不同格式只影响导入，不影响查询语义。

本轮不做：完整文件系统重放、任意脚本语义推断、旧版本查询/旧报告转换、迁移执行、根因自动认证、知识库自动合并、UI美化、新模型/新增题目。不能用后续快照封口更早未知状态。

## 2. 统一事实模型

- Source：显式登记的原始文件、稳定逻辑名称、记录归属agent（可未知）、协议、cwd。登记归属不证明派发关系。
- Record：每个物理行都保留入口，包括未知工具、thinking、普通消息、损坏JSON、失败/未完成调用。ID由逻辑源、行号、原始字节摘要决定，不依赖读写解析能力。原文读取核验字节，变化后拒绝冒充旧证据。
- Operation：只配对同一源、同一协议、唯一原生call_id的请求/返回；缺失、重复、乱序、时间未知均不猜。请求与结果各有自己的时间、原文引用。
  同记录多个调用按原生块号区分，尤其同文件一成一败不能合并；图边绑定具体操作而非仅一对记录引用。
- Relation：原生工具明确的read/write/delete及显式dispatch可以产生关系；失败/未返回只产生候选。未知脚本保留调用原文；文件名提及仅表示相关，不产生作者。导入多个源不能根据目录结构创建父子边。
- Claim：模型的原因、机制假设与建议；不是事实索引的一部分。引用存在、关系存在、原因正确分开。

不恢复全项目磁盘状态；native Write正文是该次请求的内容，Read正文是返回的观察。Edit old/new仅解释该笔补丁，不把它当完整文件或最初作者。diff比较明确选择的两个证据文本或原生补丁；无法可靠blame就返回未证及入口，不猜作者。

## 3. 查询约定

- file/agent是索引视图，不是版本状态机。`at`使用带时区ISO，`since`可选，统一闭区间。未知时间单列，只有显式包含才返回；不能用于证明截止前输入。
- 输入可用时间是工具返回时间，不是请求发起时间。截止之后的信息不能出现在截止之前的正文、预览或确认关系中。
- 文件返回已登记相关原文、原生读写与候选；同名路径不唯一必须消歧。未知工具仍能按文件名字面相关查到。
- 搜索覆盖完整选定范围，不仅当前页。多个词为字面OR，不解释正则；没有命中不等于历史不存在。
  agent inputs同时提供收到的历史任务消息与Read文件入口，messages按时间分页；两者均不代表完整有效上下文。blame terms只陈列原生补丁字面增删/保留，不认证首次作者，未知脚本继续在calls/search查阅。
- 一次允许多个查询。每个查询独立范围；不需要via，查询先后不能生成历史关系。
- 数据导入一次，查询使用持久化索引；原文按偏移读取并核摘要，不重复建立全池账本。

## 4. 展开与交付

概览只给精简目录、总量、实际返回量和下一页；不将摘要标成全文。显式原文展开保留完整选定原文，不用摘要替换。

完整查询结果及结构化元数据由服务端保存。模型接口输出可读文本；若选定原文超过传输帧上限，明确给完整长度、当前片段和继续读取入口。续帧只读取同一已保存结果，不能重新查询而漂移。这里的分帧不是宣称一帧已展开全部。

每个服务端发出的帧保存准确字节，UI自动记录查询、服务端发送及后续宿主可见观察。没有宿主观察时只标“已返回”，**不得标“模型完整读过”**。即使宿主记录证明完整呈现，也不证明模型理解。MCP不允许模型自己认证可见性。

## 5. 结论与UI

只接受一种新格式 `inquiry/1`（YAML/JSON）。每条finding含原因、相关修改引用、节点及其原因、证据、未知；机制假设和建议可选。图的节点仍只有file/agent，节点有自己的截止时间。

历史边必须按索引原生依据核回；独立检索、声明顺序、相邻节点不能补边。模型可以提交尚未认证的关系主张，但页面显示为未核连接列表，不能画成已证读写边。候选边有依据才画虚线。节点原因不因断链丢失。

红色仅代表模型认为有问题；引用无效、时间越界、关系未核分别显示，不伪造“归因已证”。页面可看查询轨迹、原文、结论节点原因；手工查阅不改写原模型轨迹。

2026-09-11 i05补充（保留同一inquiry/1格式）：通常不让模型手填edges。省略edges时，服务端从changes及节点evidence已引用的原生操作生成历史边；补出的端点明确标为“原生证据节点，未归因”，不得改写原稿、替模型填原因或标红。显式edges仍按原约定核验，不猜别的边。节点是截至时刻的历史范围，不声称文件完整状态或问题一定沿边传播。

机械状态只描述引用/坐标/已记录原生写对账；未知脚本候选另外保持可展开和未审计计数，不把每条词法沾边调用当成必须归因的修改，也不能凭valid宣称全部修改已查全。跨起点边界发起、窗口内才返回的原生写仍计入对账。语义正确性仍由冻结核心和额外错误核验，门槛不变。

## 6. 验收

工程验收必须覆盖：

1. 添加文件/增强解析不改变既有记录ID；同名源/文件拒绝歧义；字节改变旧引用失效。
2. 同一个call_id不跨源配对；失败、重复和未完成不变成确定写；嵌套文本不当成原生调用执行。
3. 迟到Read结果不泄漏到早期范围；未知时间不默认当早期事实。
4. 任意未知工具/脚本的相关原文可以搜索和展开，候选不升级作者。
5. 查询索引不扫描和解析所有源；分页可穷尽；OR搜索和完整原文续帧无丢字重复。
6. 大批量不会悄悄缺页；服务端返回与宿主实际呈现分开记。
7. 捏造节点/引用/边不通过；独立打开正确spec不能捏造它被agent读过。
8. UI展示来自同一查询内核和原稿，不再解析散文猜树。
9. 会员页真实记录：生成截止可找到Slice8实际输入/输出；修复窗口能找到mask/图片脚本和编译回执。只测试可取证性，不把已知答案提示给调查模型。

收益验收另算：沿用固定原始组、原有文件级任务和评分，用同一Luna设置跑新工具。必须记录真实交付；不能把主代理已知答案后的手工取证算准确率。未跑或不达标就明确标记，不能用测试数量/代码减少/树长替代。

## 7. 实施约束

先实现这份约定，不添加下一代兼容协议。不复制旧收集器、旧版本状态机或旧展示解析。确有缺口先确认是否属于上述验收，不以新案例无限扩展功能。

保留已有真实反例作为语义要求；旧测试依赖的内部结构不要求照搬。不删除用户修改或历史原文。实现、工程通过、真实可取证通过、模型效果通过分别记录。
