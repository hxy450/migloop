# 自由调查，证据树交付

2026-09-13；基线 8163351。此文是实施约定，不是效果已达标声明。

## 不变的底座

同一 inquiry/1、file/agent + 时间、持久化原始事件、现有 UI。调查员自由使用原始读取或 MCP，不维护 via。树是论证的证据投影，不是实际查阅顺序。原生关系实线，模型核原文补充的读写仅属于报告并保持虚线。

## 交付与核验

复用 finding.edges 声明关键交接（from/to 为本分项节点 ID，原生操作用 link 或完整请求/回执引用）。不同时间的同文件节点必须保持独立；不能因实体同名而把模型声明的中间接收、输出绕过。最终文件节点使用目标文件及观察截止时间；它的历史范围可不设 since，目标修复窗口仍由顶层 target 固定。

省略 edges 的旧卡继续加载，其自动路径仅表示已引用历史关系；新技能交付明确 edges，不能以自动连接代替论证。引用到的其它操作只给导航提示，不强迫所有相关材料接入树。独立搜索找到的正确 spec 是对照，未被读取时不造输入边。未声明或未闭合仍可保存草稿，不删除难点换通过。

读写、派发的参与者、时间与原文由共用边校验绑定。每条 claim 描述本次交接与问题的关系，但绑定成功不认证错误内容连续传播、初次作者、输入充分或历史职责。首次可见、首次引入、后来沿用、修复、运行期未验证仍须分别解释。

检查证据可使用 finding.checks，逐条包含 node、request、result、tool、claim。node 指声明该次调用的 agent 节点；请求/回执须是同一原生调用、同一实际执行者、处于节点范围。多调用原文可用 request_block/result_block 消歧。只认证调用配对和身份，不把工具成功或回执中的 PASS 认证为目标已验证；检查的对象、范围、语义仍由模型解释与人工复核。

## 验证顺序与边界

1. 真实失败机制的正确/错误成对回归：错收件人、无关 spec、晚写者冒充首因、声明冒充执行回执、失败与并发、脚本补边、同文件多时刻交接。
2. 旧卡/新卡均使用同一加载器；路径每步能由手动 neighbors 复现；原稿不改写，源摘要变化不能复用旧认证。
3. 三文件冒烟（会员、Guide、Splash），再冻结代码跑已有十文件。Luna/high，短任务加同一技能，不扩题，不重跑整套原始组。
4. 保留初稿、查验反馈、每次修订及终稿。原28点保持不变，另计错误断言的修正/误改、问题路径、修改遗漏和构树增量成本。不把删除困难结论、空问题集合、树变长算通过。
5. 若要证明查验器的独立收益，再用相同初稿和等预算普通自查做小规模对照。十文件单轮仅是开发反馈。

本轮不做新图内核、新页面、完整文件系统重放或知识库自动合并。证据包迁移及远端接入在前述回归和模型实验之后；不以格式通过宣称经验已正确。
