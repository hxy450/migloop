# 时间通路恢复已有派发关系

2026-09-11。旧版 atoms._link_dispatches / agent_atom(parent, children) / verdict._rel_dispatch / fixchain.html 的派发能力未被删除，但时间原子、v3 结论、新默认树未迁移它，属于功能回归，不是新产品需求。

本次保留旧接口，新增共享 dispatch_scope：时间 agent 的 dispatches 分区、v3 dispatch/possible_dispatch 校验使用相同证据策略。新树沿该分区展开父子 agent；agent→agent 不能冒充文件写边。文件/agent 的两种节点不变，不新增 skill 节点类型。历史 skill 仍是文件。

边界：

- 只投影账本已有的派发关联，不扩张父子识别器。原生结果 agentId 能对上子代理才确认身份；旧名称/派工文本匹配仍为候选。
- 原始调用及唯一回执可定位、成功返回，且回执在查询截止内；失败、未完成、重复身份、源漂移不认证。原文入口仍保留。
- 子代理仅在未来记录中出现，不提前公开推断的关联。没有时间的材料不当作过去事实。
- 派发原文展开受同一 since/at 边界约束；打开另一个 agent 的查询明确给出它自己的范围，不把搜索跳转或时间顺序画成关系。
- 派发事件身份与文件修改事件分开；多种目标的 UI 操作键不碰撞。
- 定位可核不证明收到全部父上下文、理解/执行任务或问题沿边传播。

tests/test_dispatch_scope.py 覆盖原生/候选、双向查询、未来/失败/漂移/重复身份、v3 引用核验与反向假边；tests/browser/time_tree_core.test.cjs 覆盖界面派发方向、时间边界和候选状态。旧派发及读写测试继续运行。真实 0723 Slice8 在写入前能查询到主会话派发的候选关系；实际 stdio MCP 与批量无损返回已验证。

不把这次恢复当作归因准确率提升。效果由独立保存的 longchain-20260911 单文件配对诊断检验；该开发案例不能证明泛化。
