# 返修调查的交付物与展示边界

当前新产出使用 `migloop-verdict/2`，旧 `migloop-verdict/1` 继续严格解析。可通过 `guide(topic="verdict")` 获取本次实际契约；`MIGLOOP_VERDICT_VERSION=1` 仅用于明确选择旧产出协议，不会重写历史报告。

## 什么由模型写，什么由系统记录

| 内容 | 来源 | 能证明什么 |
|---|---|---|
| 节点/事件的 role、reason、basis、recommendation | 模型 YAML 原文 | 模型作出了哪些主张，不等于主张真 |
| 每次查询参数、结果、via、成功/失败和实际查询范围 | 录制的工具调用 | 调查如何进行；不是模型私有推理 |
| 节点、引用、事件位置、读写关系、清单校验 | 当前账本＋来源绑定 | 对应记录存在及限定的机械关系，不认证因果 |
| 逐题支持/反证裁决 | 独立原文核验报告 | 对具体断言的有限范围评审，不能用 check 代替 |

模型不用重写一份“搜寻路径 YAML”：路径若由模型自报，反而可能与实际调用不一致。页面叠加真实录制轨迹和模型结论，两者各保留自己的来源。

## 一条归因条目的形态

`defects[]` 中每项表示一个具体问题/变化，可以共享文件和节点：

- `target_file`：本项讨论哪个文件，不带版本；只做作用域归集，不制造修复事实。
- `repair.before/after`：可选的真实版本锚点。动态脚本没有可核版本时可以省略，不能用最早/最终版凑区间。
- `nodes[]`：真实 `file:path@vN` 或 `agent:id@vK` 的角色、原因与证据。红色角色需 `basis` 明列期望、实际、双方证据和反证。
- `event_claims[]`：原始事件的作用、原因与证据。`event` 使用完整 action 引用；系统算 owner、真实效应版本或 null、此前效应上下文。模型不得自填 anchor/version。
- `entry` 与 `entry_events`：分别指本项的版本进入点与事件进入点，不能混用。
- `edges[]`：显式版本间关系主张，重新按账本核对。顺序、相邻节点、搜索命中都不自动变成读写边。
- `recommendation`：可选的独立改进建议，仍属待验证的模型主张；系统不从原因散文猜补。

没有正式版本的尾后动作不是“最近版本已经发生的事”。它在页面独立事件区显示，原文和系统上下文可以展开，但不会把上下文版本标红，不新增图节点、读写线或模型访问。

## 清单交代，不冒充已调查

`sessions(file=...)` 给出版本/候选清单与 `MIGLOOP_COVERAGE_RECEIPT`。V2 只需写：

```yaml
coverage:
  manifest_sha256: <照抄本次清单摘要>
  reviewed: []
  complement: not_investigated
```

这表示模型没有逐项作判断，系统把清单全部列为“未调查”。有具体判断时再往 `reviewed` 添加逐项理由和证据。非法/重复行不会被补集吞掉；跨文件、跨账本或变更清单的摘要不能通过。

`complete` 只表示机械交代齐全；`declarations_complete` 只表示清单每项都有有效显式声明、没有系统补集。即使两者为 true，也不证明看过原文、没有遗漏真实修复或原因正确。清单本身只覆盖账本定义的版本及候选，不是所有实际 diff 的完备证明。

## 保存与载入

当前 paired harness 为一次运行保存：

- `verdict.yaml`（或原 JSON）：模型的完整原稿。
- `verdict.json`：原稿、来源绑定、清单与检查结果等运行侧记录。
- `findings.json`：按历史 repair 文件、独立 target 作用域归集的无损读模型，含节点/事件原因及建议；不覆盖原稿。
- `transcript.jsonl`、`metrics.json`：真实调用、交付范围、用量和运行身份。

`reference` 交付模式下，模型先将完整草稿交给 `check`，最后只引用该次真实核查返回的账本身份和双哈希。harness 从同一运行的认证调用中取回原稿，不要求模型再抄一遍长 YAML。

页面通过运行目录载入这套产物：`/api/insight1/fixchain/<sid>?probe=<相对MIGLOOP_RUNS的运行目录>`。**只有 YAML、没有录制轨迹，不能证明实际调查路径。** 当前 UI 的完整回放入口是运行目录，不是任意单个 YAML 文件导入。

点击查看器中的原文或上下文，是人的后续查看；不能回写成模型当时看过。失败/未完成查询、灰色未查询端点、候选关系和无关系跳转必须继续区分。

冻结调查可显式设置 `MIGLOOP_FROZEN_POOL`、`MIGLOOP_FROZEN_ANCHOR` 及 `MIGLOOP_FROZEN_ROOTS`（根路径 JSON 数组，含 anchor）。清单内的 session 都是同一范围的入口别名；页面与 sessions 显示这个范围，不通过换 SID 暗换账本。清单由调用者选择，不凭 cwd 相同推断工程关系。查看该运行时应使用相同配置；审计脚本按运行元数据恢复，而不是推测。未开启该模式的历史运行继续使用原有范围语义。

接口与显示可核，不等于本工具已经证明比原始转录调查更准确或更省。比较应同时查看固定题目上的独立语义裁决、完整 input+output 成本和真实 UI 回放结果。
