# 时间探索树

默认返修页使用 `time_tree.html`；`time_tree_core.html` 负责可独立测试的时间身份、关系与主张过滤。旧 `fixchain.html` 保留给旧消费者，不再作为服务端默认页面，也不再复用它的全局 probe 状态。

## 一个节点、一套范围

节点身份是 `(file/agent, canonical key, at, since_ts)`。时间精确到微秒，时区等价表示归一化。版本只提供关键事件时间的快捷选择；同一时刻可能包含多个事件，时间不是单个事件的唯一身份。旧版本锚点通常是发起/记录时刻，不应假定调用已经完成。

手动总览与 MCP 共用 `atom_queries → temporal_atom`。读取/写入分区、消息、原始记录、搜索、diff、blame 和原文展开都沿用明确的范围。查看器可以独立搜索和换根；查询顺序不产生历史读写边。

## 关系与结论分开

- 文件的历史写入操作可以展开该调用所属 agent 的请求时刻输入范围；agent 的读取操作可以展开返回时刻的文件证据。这些时刻不是精确磁盘修改时刻。
- 实线表示已有依据的历史操作，不表示唯一作者、正确读取了内容或缺陷传播成立。正文交付状态另列。
- 候选读写使用虚线。没有明确文件目标的调用、单纯提及、无依据的模型边只保留为材料，不变成连边。
- 模型主张要求文档身份已绑定、节点实体与时间精确匹配才上色。红色是模型认定的问题，不能当成机械核实了归因。
- 多条缺陷分别保留原因、支持证据、反证和未知。同一实体其他时间的主张不“连坐”；可独立打开其准确时间。
- 载入模型结论后仍是一棵可展开的时间树。没有已核关系的主张保留为独立时间根，不为美观补边。
- 原始模型查询回执与当前浏览器手动查阅分别展示。运行时返回、模型可见输出、全文交付和理解不是同一件事。

## 验收

`tests/browser/time_tree_core.test.cjs` 验证时间、候选关系、精确绑定及无效边过滤。
`tests/test_time_tree_ui.py` 验证默认页面组合、脚本安全和可执行 JS 契约。

`tests/browser/time_tree_smoke.cjs` 使用实际 Chromium 点击页面，覆盖报告载入、文件→agent→文件、载入后手动换根、截止时间、版本快捷时间、节点主张、原文展开、上下游同列不重叠、刷新复现时间范围和已核模型边。它同时核对手动点击前后的模型报告及原始查询轨迹没有被改写。

浏览器检查不重新运行调查模型，不修补模型 YAML，也不重算归因准确率。冷查询仍有原始记录全池扫描成本；本次 UI 改造没有证明调查 token 或运行时间下降。
