# 本地实验产物保留规则

测试代码和正式实验记录不是一次性测试临时目录。

- 保留原始 session、冻结输入池与代码、ground truth / 仲裁、固定原始组基线、模型报告、调用回执、评分和 manifest。历史失败也属于证据，不按分数筛掉。
- 保留当前页面验收的截图、浏览器错误与复现脚本；浏览器 user-data-dir 是可重建缓存，不是验收证据。
- pytest 的 `tmp_path` 内容可重建。日常运行使用 pytest 默认临时目录与自动保留策略，不再为每次运行在 `projects` 下新建随机 `--basetemp`。
- 本机系统 Temp 下既有的 `pytest-of-hongy` 权限异常时，设置 `PYTEST_DEBUG_TEMPROOT=C:\Users\hongy\projects\_migloop-scratch`，仍由 pytest 自动创建和轮换编号目录，不修改系统 Temp 的权限。
- 确需指定 `--basetemp` 的复现必须使用明确的专用临时目录；不可传仓库、实验根目录或输入池。pytest 会清空显式 basetemp。
- 临时产物应集中在一个工作目录，不再散落数百个 `_migloop-test-*`。正式 run 仍不可覆盖、改名或重新解释为新运行。
- 清理先列出确切目标并验证路径，排除正在使用的目录、目录链接、无法读取的目录。优先移入回收站，记录实际成功/失败；进入回收站不等于释放磁盘空间。
- 不仅凭“旧”“重复文件名”或“测试”字样删除。冻结实验可能复用早期实验的输入池路径，必须保留这种依赖。
