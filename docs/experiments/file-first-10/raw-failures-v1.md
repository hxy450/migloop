# 十文件 raw baseline：实际失败与工具需求

2026-09-10。只分析本次冻结的20份Luna原始组调查，不使用工具组输赢倒推解释。分数见[结果](baseline-v1-results.md)，原始程序索引为实验目录的`raw-recording-audit-v1.json`。

下文“step”是本次调查的原生外层调用顺序，“L”是该跑`transcript.jsonl`的物理行；不是历史会话里的动作号。读取整个文件的命令，不代表未截断正文都交付，更不代表模型理解了正文。

## 1. 修改清单漏了，最后却断言只有这一组修改

**会员页 F10-01 rep1**：step5（L43→46）自行递归解析时只接受`Edit/Write/MultiEdit`，实际返回两条去`private`操作。历史视觉修复的大量改动通过Bash脚本写盘，不在这个过滤器内。模型最后把“两条被解析到的操作”说成全部实质修改，并把新helper追错到初版。其他广搜并非完全没有做，但不能修复这份不完整清单的证明缺口。

**Splash F10-02 rep2**：step14（L104→107）进一步筛`toolUseResult.filePath/oldString/newString`，只返回后期路由恢复那条原生Edit；该返回还只保留old/new各260字符。另一批真实Bash修改没有这个结构字段。最终报告正确解释系统栏，却明确否认BACK/进度有后修；真实fixer的L346→347与352→353有对应成功写入。

**工具需求**：完整原始事件索引是底层，解析出的修改账是上层。文件范围同时列确认修改、未决效应和相关调用；未知工具/脚本不应消失。结论提交后对“观察到的修改账”和解释做差集，但不能把一个脚本机械拆成多个预设缺陷问题。清单覆盖的边界必须公开，不能承诺任意脚本效应都已恢复。

## 2. 解析失败和解码失败被误用成没有材料

**Splash F10-02 rep2**：step3/4/6/11使用`ConvertFrom-Json -Depth`，错误被`catch {return/continue}`吞掉，返回只有标题或空白；step12（L90→93）取消吞错后，原生返回明确显示`NamedParameterNotFound`。本地只读复现也确认当前PowerShell 5.1不接受这个参数。随后移除参数才取出记录。这是可复现的调查脚本错误，不是池内没数据。

多份调用没有给`Get-Content`指定UTF-8，实际返回出现`è¿...`等乱码；例如F10-02 rep2 step14，F10-01 rep1 step6。环境里的Python UTF-8设置并不保证PowerShell读文本时采用UTF-8。

**工具需求**：统一解码、格式识别、原始id配对、时间过滤；解析失败数量明确返回。搜索零命中不能把解码失败、过滤掉的格式或未扫描文件算入“已搜索且没有”。

**对照边界**：解决这些问题未必需要知识图谱。一个可靠的通用原始JSONL读取器也可能获益。后续若提升主要来自这里，只能先说统一取证有效，不能宣称两原子本体或漂亮的树使推理更准。

## 3. 广搜返回很多，却没有交付完关键修改

**Dice Entry F10-07 rep2**：step11（L83→86）用“整条JSONL含文件名且有Edit/Write”筛选，并非严格判断该调用的目标文件；写`verify-report.md`但正文提到EntryAbility的记录也进入输出。实际返回标记截断，前面先出现长验证报告和测试桥，最终却否认后期ECAT observer修改。其所引晚期完整源读回本身含observer，但不能据引用就推定它已经收到这份完整原文。

本次338个外层返回中146个含截断提示。这个数只是标记扫描，可能包括引用历史截断提示，**不是146次已证明的关键证据丢失**；所有文字累计590万字符也不是已理解材料量。

**工具需求**：精确作用对象与词法提及分开；先返回紧凑索引、总量、未交付数和续读位置，可批量开多条字段/调用。摘要不能冒充原文。默认折叠不是隐藏，搜索应覆盖完整范围，而不是仅当前页。

## 4. 找对局部代码原因，却补出了没有证据的上游故事

- F10-06 rep1把底部遗漏归于明确留给Slice的延期任务，实际早期FWD-REF谈的是**顶部**。rep2则正确追到converter所读mapping缺4dp；它没有因为别的资源actor早读到4dp就认定converter收到。这说明必须分清“池内存在”和“当时输入已交付”。
- F10-08 rep2正确解释后期身份任务扩大范围、复制图标到AppScope并切引用，但又称初版把工程内存在误当成AppScope可解析。旧AppScope里已有被引用的`app_icon`；历史记录也明确选择保留脚手架。新资产要放进AppScope，不等于旧引用曾经缺资源。
- F10-03两跑都解释了按钮视觉/测试/注释整理，却没把具体交付规格`Roll`与运行`ROLL`的矛盾讲全，也未完整追到console最先由视觉修复加入。泛泛说“主题转换/质量检查”不等于恢复了输入和首次引入链。

**工具需求**：让模型容易批量打开生成者当时的输入、该次写入前后片段和上游交付材料。保留“输入存在/读取已证/含义正确/实现遵守”四个独立问题。时间和边只能约束事实，不能自动判定认知原因。

## 5. 后期快照回推、局部报告扩大成全阶段事实

- F10-01 rep1把返修新helper错归给初版converter；引用的早期L81实际是spec编辑，没有声称的helper源码。
- F10-10 rep2把生成结束1小时41分后的配置读回说成生成结束时状态，并以此给出排他原因。后期缺配置是观测，早期精确状态仍要另证；报告核心product引用原因是对的，辅助回推证据不足。
- F10-09 rep1将某个worker的`BUILD_NOT_RUN`扩成生成期没有编译；根池有真实BUILD SUCCESSFUL。rep2较谨慎，限定为worker报告、交互验证缺口，没有因此再判成全阶段未编译。
- F10-07 rep2否认修改后有成功UI结果；后期另一条Python replay实际有10/10通过，但桥键仍`NOT_ASSERTED`。正确表述应同时保留替代回放成功与原框架/完整桥协议未证，不能选一个抹掉另一个。

**工具需求**：每条材料自动携带来源、actor、发生/可见时间和证据类型；“报告说成功”“实际构建成功”“特定产物的行为复验”分开。file/agent展开与search/diff/blame继承显式时间范围，不把较晚首次观察向前封口，不靠模型手抄定位符。

## 6. 下一步最小可检验实现，不先扩大图谱

保持已冻结raw结果，不重跑挑最好。优先完成一个UI/MCP共用的只读取证内核：

1. 原始池注册、UTF-8解码、原生事件索引和失败/未配对回执清单。
2. 不可变`pool + file/agent/全池 + 时间区间`查询句柄；所有展开、检索、diff、blame继承范围。版本仅兼容/展示，不当信息围墙。
3. 精确读写、可能效应、纯提及分层；批量展开、多关键词搜索、完整分页。零命中/截断必须可审计。
4. 服务器记录调查轨迹和实际交付，模型只负责调查与结论；YAML节点原因引用服务器句柄。模型不手写via，独立查阅不画成历史读写边。
5. 对已观察修改做结论差集；引用定位与语义支持分开。未知上游机制可以如实未知，不逼模型编skill/上下文故事。

先用原始反例做离线合同验收，再以同一Luna、任务、池和预算跑工具组。若投入较大，应增加“通用原始读取器、无图谱推理”消融，判断价值来自读取器还是链路。它是新对照，不覆盖本次raw分数。任何共同环境变化（例如更换shell/模型/预算）都须新建匹配实验，不能偷偷享有不同条件后继续称完全配对。

### 接受/拒绝条件

- 正确归因覆盖与主张精确率不能靠少答换高分；同时报全文件核心通过、重大错归及所有遗漏。
- 新增观测状态不得写成历史读写实边；原文不能支持的模型边只显示为待核主张。
- 若质量不改善且成本不降，停止宣称工具已有效，继续定位具体失效环节；不能以引用可解析/UI好看代替归因效果。
- token须同时报总输入、缓存、输出；耗时计建账与后处理。20–30%节省仍是待测目标，不是本轮成果。
- 十文件是同三项目的困难开发集，不是广泛泛化证明。管线改进能否减少下次真实迁移错误，仍需后续干预实验，本轮不做。
