## 1. 什么算完成

对一个具体被修问题，报告证明：

> 相关输入在当时正确、清晰且足以约束这项行为，并已实际交付 → 某次具体输出偏离它 → 该偏离与目标文件的实际修复对应。

满足即可判该项有界归因完成。允许一项必要输入，也允许多项互补输入；不按文件数量、跳数或引用数量得分。输入充分只针对正在解释的行为，不宣称整份 spec/skill 全部正确。

这里的“具体输出”可以是首次可证偏离，也可以是后继有明确职责却继续保留偏离。必须说清引入/保留，不把最后写者当唯一责任人；不要求在无法证实时找出全历史唯一最早作者。

不再把这些作为该项完成的额外必要条件：

- 追到正常 skill/spec 的作者，再证明其全部上游正常；
- 强制解释上下文长度、模型心理、编排设计为何导致失误；
- 强制穷尽每个下游检查为何没拦住；
- 必须证明修改管线会减少下一次迁移错误；
- 为了使树更长，把每次无关读写也串进去。

如果报告主动作了上述机制断言，仍要核其真假。**不要求说，不等于允许说错。** 某项局部归因已经成立，不因缺少可选深层机制而被改判未完成；额外错误和展示错误另列。

## 2. 对原始组、工具组相同的证据要求

1. **输入内容**：指出实际条款/源码行为及适用范围，不能只报一个文件名或说“输入正常”。源码引用也可以是充分的操作指令：例如明确要求追读某资源而生成者未执行；这条等价路径需要真实任务义务和执行记录，不强制要求数值字面量已粘在派单里。
2. **实际收件**：该内容在输出之前进入相应执行者的历史上下文。原生 Read、命令回执、派单粘贴、实际 skill 注入等均接受。池里有、别的 agent 看过、后来修复者看过，都不能直接替代收件。
3. **偏离位置**：指出相应 Write/Edit/脚本效应及偏离的具体片段。读过文件不证明遵从，原生写边不证明所有 reason 都正确。
4. **关联目标**：不是无关坏代码；偏离进入目标文件，并对应所解释的返修改动。无需在语义成绩里列满所有中间节点，但不能存在已被覆盖/修好后再出现、却仍错误认定连续传播的已知反证。

报告可用散文、表格或树给出以上证据。原始组无 YAML/节点 id 不扣此分；工具组有树不加此分。不得用审阅者新找到的收件/输出代替报告自己的关键推理，再判它完成。报告已有可核原始坐标但没有复制长段原文，不算缺证据。

“输入里有 drawable 路径”与“生成者收到4dp正文”不能互换。但若确实证明任务要求追读该 drawable、执行者没有完成这项读取，可按“明确取证义务未执行”归因，不必无限追资源作者。

## 3. 不是所有修改都是生成错误

同一28项中存在其他可完成的有界解释，不能为了构造“好→坏”强行指责生成者：

- **后置要求/范围变化**：当时实际交付的范围与后期新增要求、相应修改可核；说明为何不是原始违规。
- **明确授权的延期/未决方案**：实际派单要求保持挂起，生成输出遵从；区分功能未完成与执行者犯错，说明后来如何解除。
- **返修新引错误**：定位返修输出首次引入的具体偏差及随后纠正，不倒算初始生成。
- **原始记录确实到头**：如缺失未保存的子线程，说明已知事实和具体不可证边界；不得伪造好输入或作者。可接受为有界停止，但必须单列“证据不足”，不能记成已找到输入→偏离的完整归因。

“我没查到”或预算耗尽，不足以宣称原始记录不存在。正常边界不是“没有更多线索”的同义词。

## 4. 评分与展示分开

保留 [scoring-core.json](scoring-core.json) 的原28项和旧局部得分，v2逐项另记：

| 状态 | 含义 |
| --- | --- |
| established | 上述有界因果解释成立，包括有据的范围变化、授权延期、返修新引错误 |
| partial | 修改/局部原因基本对，但相关输入、收件、偏离定位或目标关系还有可查而未核的缺口 |
| bounded_unknown | 源记录有具体不可恢复缺口，报告准确保留未知；允许停止，不伪报找到根因 |
| omitted | 未解释这项实际修改 |
| wrong | 对该项核心因果、输入/责任阶段有反证或无据确定性归责 |
| unreviewed | 尚未按v2审阅，不当作0分、通过或未知 |

完整批次主指标为 established/固定28项，并列文件等权覆盖、wrong数、bounded_unknown数和已审阅数。分母固定，不丢掉难项或未知项抬分；未审完28项不得报完整批次新ACC。不要把 established 数叫全文断言准确率。

独立报告三层结果，不用一个“失败”抹掉所有进步：

- **归因是否成立**：上述语义状态。
- **证据树是否忠实**：需要展示的输入/问题/目标能载入，节点时间、原因、实际关系与原稿一致。声称传播时中间内容须有据；部分Read不得标成完整Read。树未完整展示可以是交付待修，不自动推翻已经成立的局部归因。
- **优化建议**：与已证问题相符、可操作、有验证办法即可；机制猜测标假设。不要求先验证真实迁移收益才让归因通过。

任何额外错误都按原句独立记录。足以推翻核心证明的错误使该项wrong；无关或后续节点的错误不抹掉正确的输入→输出对照，但禁止把整卡宣传为全对。
