## 3. 固定评分口径

同时报告，不混成一个含糊的ACC：

1. **主指标：文件等权正确归因覆盖率。** 每文件正确核心数/该文件核心总数；同文件重复先平均，再对10文件平均。避免6项的大文件完全支配结果。
2. **辅助指标：核心单元等权覆盖率。** 所有correct/所有预定核心单元。原始组两次共56项，完整工具一轮28项。
3. **全文件通过率。** 核心全对且无已核重大额外错误的运行数/预定运行数。另列核心全对但有重大额外错误的文件。
4. **额外主张准确性。** 对实质归因主张按原句去重，分supported/contradicted/unsupported-as-fact/hypothesis；报告精确率及审阅覆盖。未逐句裁决就记未测，不用核心覆盖率代替主张精确率。
5. **工程与证据审计。** 引用定位、时间、关系、实际输出可见性、未解释修改、未知效应、问题链状态分别报，不能替代语义分。

单元使用correct/partial/omitted/wrong。核心原因和责任边界有原文支持即可correct，允许合并/拆分表述；缺辅助细节不清零。原文足以回答却只写未知是未完成；原文确实不足时有界未知可以正确。重大错误必须有实际报告原句和原始反证，涉及中心修改、原因、责任阶段/作者或行为验证；遗漏、合理未知、格式错误本身不自动是重大错误。

超时、无交付、错误最终hash、机械失败均保留。批量请求里失败的项另计，不能把调用成功返回一个ERROR当原文成功打开。不同轮最好答案不能拼成“十文件全对”。

## 5. 自由调查，结论阶段用证据链反查主张

调查过程中自由用raw和MCP，不维护via、不按UI树强制行走。记录实际操作是服务器/运行器职责。结论交付时，再核每个被判有问题的节点如何影响被修文件的对应改动。

```text
任意顺序调查 → 提出带证据的原因 → 核时间和逐跳影响链 → 补查/修订/降级 → 保存最终原稿与UI
```

### 链应证明什么

每条finding的链围绕同一个问题：问题节点（agent或file及时间范围）→实际交付/读写/派发或有原文支持的影响环节→被修文件的相关历史内容→对应返修改动。每个问题节点和相关环节带原因、原始证据、时间和未知。不是把所有查过的节点串起来，也不要求整图只有一条树枝。

需要分别核实：

1. **身份与事实边**：原生调用的精确actor、路径、块、请求/回执；不是独立搜到的spec就算曾被读取。派发只证父子调用，不自动证明某段内容传递。
2. **时间连续性**：用实际事件时刻，不用节点截至时刻代替。写后的Read不能解释写前输出；同名文件跨时间不能默认内容连续。宽范围节点即使拓扑连通，也要逐跳核事件顺序及中途覆盖/删除。
3. **问题内容传递**：读过/写过不等于这个问题沿边传播。核所读片段、实际写出和后续保留/改写；输出完全被覆盖或传下去的不是该问题片段时，不能用无关路径凑闭环。
4. **目标绑定**：终点不只是任意同名文件，而是这次归因涉及的历史内容和目标修复引用。某段坏输出最终没进入目标文件，是推翻这条归因的有效反证。

“10:10 agent写错了，之后没有任何影响到目标”的例子要分两类：

- 原始证据显示该输出未被采用、已覆盖、时间不可能或后续读取的是别的内容：原结论应修订/撤回，而不是补漂亮的边。
- 工具索引没有读边，但原始shell、脚本正文、派工中粘贴内容、生成器/构建消费等证明有传递：登记漏识别及具体原文。可形成明确标为“原文支持、解析器未认证”的关系主张，不能伪装成机器已确认的原生读写。单纯模型说它存在不够。

因此，“图里没有边”本身不是反证；“原文显示没有这次影响”才可能反证。同样，图中有路径只是必要核查材料，不是因果充分证明。这是收尾一致性检查，可以发现false claim，不能保证消除全部错误。

### 交付状态与UI约定（待实现，不是现有schema字段）

- **已核链**：实际关系、时间与目标绑定可核；节点原因仍标为模型主张，另作语义裁决。
- **有原文支持但含推断/候选的链**：逐边标依据和置信边界，不算全链机器确认。
- **未闭合**：显示断点、缺哪份证据、已经排查什么；可以保存局部发现，但不能将更深根因作为已完成证据链交付。
- **被反证**：保存原主张和撤回依据，不能悄悄删掉轨迹。

每个origin/propagated节点都应有路径状态；不能只画红而不说明它如何到达目标。宣称“链路完整”的条目必须没有隐藏断点；不强制把所有未知条目补成完整。页面展示最终原因、逐跳证据、真实操作轨迹以及这些状态。候选画虚线；只因查询先后相邻不能新增历史边。raw绕过MCP查到的证据也必须核回原始位置后才用于最终图。

新增报告指标：有路径状态的问题节点数/全部问题节点数；已核/候选/未闭合条目数；错误边和倒序边数；收尾核链前后的主张保留、改判、撤回及原文理由。分母仅包括模型声明的origin/propagated节点，不包括服务器补出的中性context端点。保留核链前草稿，才能观察它是否真的纠正错误，而非只做漂亮展示。无问题节点时分母为零报不适用，不报100%。

待实现的最低交付门槛：所有模型问题节点都有显式路径状态；宣称“已核链”的条目必须实际到达对应目标、无隐藏候选/断点或倒序连接。未闭合条目可以保留，但不计入已完成证据链。路径状态覆盖100%不等于已核链100%，更不等于语义准确100%。

当前实现已有引用/目标/节点时间范围、原生边绑定、缺失关系提示、修改对账与证据复核提示；尚未强制问题节点到目标的可达性，也没有自动认证内容传播。i20 Splash的E:origin无出边但mechanical_status仍valid，已经说明缺口。自动补边主要是已引用读写，显式派发可以核验但尚未统一自动补齐。上述状态/指标是下一步验收规格，不是假装现有能力已经完成。
