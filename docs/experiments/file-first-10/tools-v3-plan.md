# tools-v3：时间原子概览验证（结果产生前登记）

2026-09-10，源码提交 `2fe4ffc`。当前没有v3模型分数。

## 待检验假设

两原子默认先给时间安全的输入/输出与原生正文导航，能减少把后期观察当生成状态、遗漏生成输入和早期写入的错误；新增的查询与输出负担不能抹掉此前的token优势。

这是一个迭代版整体比较，不是只改变一个开关的因果消融。相对v2还包含已记录的details兼容、正文入口、注释分页和回执/效应分离。若有效，不能直接断言收益全来自两原子或时间坐标。

## 固定项

沿用baseline-v1十个不同被修文件、两个重复、Luna medium、两并发、同原始池、同生成/观察边界和相同超时。调查员不知道预设问题数、标题或答案。原始组不重跑；raw、tools-v1、tools-v2及其裁决不覆盖。

沿用已冻结的28项核心责任边界与主张计分；不加强或放松唯一作者、深层机制、局部责任的要求。结构化最终稿、所有输出/推理及后处理成本照计，没有自动格式修复轮或失败换模型。

仅新增有独立字节绑定的runner适配层，以验收新的默认overview数据形状；既有启动/排队/任务/prompt/settings/解析器不变，旧runner文件不编辑。新源包及wrapper在运行前冻结，运行中不替换。

## 先验收入口，再跑模型

- 原样重放已保存Member批量10项/100k预算：确实交付的默认入口应包含最早真实写入及对应生成输入导航，而不是仅相关提及前缀。
- 原样重放Dice Index批量24项/30k预算：统计ok/error/deferred和实际交付，保留“count-only不等于操作/正文已读”这一限制，不把未改善项目藏起来。
- 原文/分页查询必须真能执行并保持明确范围；网页独立查询不能改变模型轨迹或历史边。

## 如何报告结果

主指标仍是文件等权正确归因覆盖，固定原始值73.8%。同时逐文件列correct/partial/missing/wrong、整文件通过（原始8/20）、实质主张精确率（原始73.6%）与重大错误（原始11次）。不得只报更好看的精确率而隐去遗漏。

要宣称该版在这份开发集达到“更准”，至少主指标高于原始组，整文件通过与主张精确率不低于原始组、重大错误不增加。另报总token、非缓存输入、输出和端到端时间，省token不是降低归因要求的理由。单点胜出仍不证明用户总体会胜出；这10文件来自三个相关项目，且已暴露用于迭代。
