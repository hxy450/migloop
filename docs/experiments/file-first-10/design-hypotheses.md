# 时间范围与自动审计：先登记设计假设，实验后更新

2026-09-10。此文记录已讨论方向，不宣称都已实现，也不是被测调查员 GUIDE。生产实现暂冻结于 `88b2e2f` 的分阶段时间查询；它仍有 legacy/version 接口、单行展开与 YAML/UI 版本坐标，不是完整统一方案。

## 统一语义

`agent + 时间` 是该 agent 在截点之前的全部已记录可见转录内容；不能只剩解析器认识的读写。`file + 时间` 是相关已证/候选操作，以及输入、命令或返回中出现该文件名的调用。**提及只是相关材料，不能自动变成候选写者。**

一次查询的范围是不可变的 `(源池, agent/file/全池, 截止时间, 可选起始时间)`；展开、diff、blame、搜索继承这个范围。并发请求不得用一个隐式“当前节点”相互覆盖。模型可以自主打开其他范围，不要求它维护手写 via 路线。

调用按原始 id 配对；发起与返回各有时间。截止前发起但截止后才返回的正文，不能算截止前已看到；未来返回首次出现文件名，也不能反向污染此前文件检索。未完成、失败、未知时间、重复 id、未解析工具均保留并标边界。

版本可作兼容地址、diff 端点和展示注记，但不能遮住两次已知版本之间的相关不透明操作。时间过滤解决信息可见性和先后误用，不会自动发现未知写效应，也不会证明每条内容是谁造成的。

## 展开与批量

- action/record、diff、blame 是原子内部取证展开，不为了画图增加第三类因果节点。
- agent/file/全池搜索使用同一时间合同，搜索全范围而不是当前输出页；支持多个关键词（明确 literal OR/AND 或正则语义），定位返回原始调用。
- 已知的多条调用、片段、diff、多 agent/file 和多关键词可以一次批量查；逐项返回范围、成功/失败、交付量和截断续读位置。部分成功不能当全批已读。
- 首屏只给辨认方向必需的摘要和证据入口；正文、候选、词法提及、长输出按需展开。省略必须可发现、可穷尽，不能靠“可展开”代替模型实际调查。
- 有依赖的下一步仍需等待上一步结果。批量解决交互税，不等于自动改善推理；原始组也能用一个脚本批量调查。

## 页面必须区分三层

1. **历史关系树/图**：只有 file 与 agent，已证读写实线、有依据的可能读写虚线。版本视图可分组，但不同时间和责任事件不能混为一笔。
2. **调查时间线**：服务器自动记录真实调用、范围、返回、展开、搜索、批次、失败与截断。独立查阅仍可展示，不能为了连成树发明历史读写边。模型无需抄长 hash 或编写路线证明。
3. **结论叠层**：结构化 YAML 将断言、节点原因、支持/反证和未知挂到精确实体/时间/事件。红色是模型主张，引用有效是定位核验，断言成立是另一个语义核验状态；修后节点不能因旧缺陷仍被画成当前有病。

例如：模型全池搜索到了写对的 spec，但生成 agent 没有已证读它。spec 可以作为独立调查节点与反证，不得画出 spec → agent 的实线；有候选读取依据才画虚线。搜索命中→打开片段可以记录调查选择来源，但不是历史读边，也不能声称知道模型脑中为什么选择。

查询轨迹来自运行记录，结论来自模型结构化输出；二者对照。树要便于复查，不以漂亮为由补齐不存在的路径。模型指认账本未收录的读写时可提交原始证据作为待核主张，不能仅靠纪律性直接升级为事实。

## 已观察问题 → 待验证设计响应

以下来自旧三文件的 [原始组原生调用复核](../file-first-luna/review-v2/raw-investigations.md)，不是十文件新实验的结果。

| 已核问题 | 候选响应 | 必须测的副作用/未解决项 |
|---|---|---|
| 目录/glob/JSON 解析失败导致漏子代理 | 注册完整源池；统一解码和原始调用索引；解析失败单列 | 索引本身不应遗漏未知格式；不能把零命中当无需求 |
| 只取正文前缀，关键 patch 在被截部分 | 明示截断、可批量按字段/调用展开、修改差集 | 首屏摘要是否误导；返回多了是否降低注意力 |
| 只查后期输入，误用晚期代码解释早期状态 | 输入/返回各自截时；可切换 agent/file 历史范围 | 时间不能自动判作者，也不能代替原始输入追溯 |
| 找到了变化但总结漏写 | 自动修改登记与解释差集，不预告缺陷答案 | 不透明效应仍有缺口；不能将每条 patch 强拆成一个原因 |
| 以报告摘要替代源码、以 build PASS 代替行为通过 | 标证据来路与验证层级，可展开支持及反证 | 标记是否真正改变模型归因，而非只是增加 token |
| 工具组花时间维护 via/YAML 引用、重试格式 | 服务端记录路径、返回短稳定句柄；结构化输出与调查解耦 | 引用能解析仍不等于理由成立；不能强制浅调查后赶交表格 |

反例：旧会员页两次 raw 都识别了 private helper 是返修引入，不能把“后期错误归给生成者”硬写成该 raw 案已发生的错误。工具组也会错；以上需求必须针对真实轨迹逐项核，不用一个时间故事解释所有失败。

## 后续更新纪律

十文件参考与 raw 冻结后，为每个失败填：原始步骤/交付证据、失败类别、可能响应、无改工具的提示/包装对照、验收指标。优先做能在未提示答案的任务上纠正错误的最小改动；若批量或摘要裁剪只能省成本，就如实报告，不包装成准确率提高。

机制优化仍单列：从“正确 spec 被读到但未实现”可以定位输入/输出不一致，不能自动断言 skill 缺陷、上下文过载。下一阶段需另外设计同 app 干预复跑，才能说沉淀的规则让错误减少；本轮不执行该阶段。
