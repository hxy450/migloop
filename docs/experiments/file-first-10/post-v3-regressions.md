## 字面OR重复词不应终止检索

在已完成的F10-02 rep1中，同一次搜索同时给Back/BACK，因lower重复被工具拒绝，模型未重试。源证据本身没有歧义：对不区分大小写的OR，重复词幂等，不应让整次调查失败。

后续工作区修复：保留输入长度/类型/空词限制及q互斥要求；按lower去重，保留第一个拼写与顺序。允许去重后的一项列表，也允许直接提交一项，使多层规范化幂等；不将字面量改成正则，不去掉词内或首尾空格，不扩大时间/实体范围。

测试同时核原始池内大小写两种记录只各返回一次，截止后的记录不泄漏，批量/标量回执仍可核。修好这一个查询不等于该报告整体归因会正确；v3的实际失败与分数照旧保留。

## 同一操作不应在概览与修改清单使用两套id

新概览给Action/关系生成了一套native哈希id，而changes使用已有的源事件id。已完成报告把概览id填进findings[].changes，无法与修改清单核回；即使统一id，也仍须核对该事件是否属于待解释修复范围，不能把生成事件拿来冒充修复覆盖。

后续改为两种原子、changes与已确认操作diff/blame共用已有源事件身份函数，不改changes原有id语义。观察区间diff/未知作者blame不借用单笔写入id。一个调用的多个目标可共享源事件id，关系另由path/kind区别。底层原生事件id仍只标识原生调用，不是目标修改清单id。已保存v3报告不改写，不补造原先不存在的覆盖关系。

提取持有Action时可直接使用的纯身份函数，避免在整个agent遍历里对每个动作再线性查一遍。验证同一Write在file/agent/changes三处id相等、增加解析动作后id不漂、导航仍不算读过正文。
