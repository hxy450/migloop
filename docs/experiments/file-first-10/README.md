# 十个困难被修文件：先核事实，再用原始组诊断工具需求

2026-09-10。状态：**十文件原始组20跑全部结束、逐条裁决完成。** [最终结果](baseline-v1-results.md)：文件等权正确归因覆盖73.8%，单元等权32/56=57.1%，实质主张精确率64/87=73.6%，全文件核心通过8/20。原始调用的[失败诊断](raw-failures-v1.md)与[范围审阅](raw-scope-audit-v1.md)已完成；尚未跑新工具组。

本目录是审阅端材料，不能进入被测调查员上下文。它取代旧八候选计划的执行顺序，不改写旧实验产物和分数。

## 本轮决定

先做十个真实被修文件的有界参考，再跑 Luna 原始组，再分析实际失败，最后决定工具改什么。暂停生产 MCP/UI 重构，不以两原子、时间查询或新 schema 已实现为继续堆功能的理由。

用户目标排序：归因正确且能指向可检验的改进 → 调查与结论可审计 → token 和时间。此轮不重跑实际迁移，不把合理建议宣称为已证明能减少下次错误。

文件与 agent 是合理入口，但工具是否更准是待测命题，不是前提。原始组也可以记录调用、保存原文引用；我们的优势应来自可靠取证、自动对账、减少误用信息和复查成本，而不是声称原始组天然不可审计。

## 顺序与退出条件

1. 从 0723、DiceRoller、两份 AIPPT_830_test Codex rollout 中核实候选。十个不同文件，不是十个预设缺陷问题。
2. 对每个入选文件列完整的已知后置修改事件、调用成功/失败、脚本等未决效应；追溯生成期内容、可见输入、后续修改动机及反证。无法核实的因果明确未知。
3. 参考作者与复核者分别核原始位置、字段、阶段、竞争解释；争议保留，不能靠同一段报告的多次转述投票。冻结参考、原始池、任务、评分合同及哈希后才能跑调查员。
4. 固定 `gpt-5.6-luna`、`medium`，每文件原始组两次独立运行；同一任务、工具环境和停止条件，不选最好的一次。不重跑旧基线来掩盖失败；旧三文件的历史结果继续保留，但有宿主技能污染等条件差异，不冒充本轮同条件结果。
5. 逐条核验原始组答案与实际返回给模型的材料，区分没找到、没交付、交付但误读、发现但漏写、证据不足却强归因。将复现的失败映射到工具需求。
6. 后续工具组与冻结原始组比较；如改变模型、任务、原始池、宿主指令、输出预算或限制等共同实验条件，应另建匹配对照，不能继续称完全配对。

## 入选纪律

- 必须有生成结束后目标文件实际修改的原始证据。仅被提及、计划修改、子代理说已修改但没有可核效应，不作为十个主样本的资格证据；可留作额外的证据不足负例。
- 生成结束不等于整份 rollout 结束。以当时 execute 完成的原始事件为边界，后续同会话修复也可能合格；记录边界原文与时间，不能靠文件日期猜。
- 困难按历史结构选择：多个作者/阶段、输入交付与实现不一致、后置要求、修中引错、脚本批量改动、报告与源码不一致、验证边界。不能按原始组失败、工具组获胜来选。
- 旧三个文件标为已跑开发样本。曾讨论过答案的其他候选也标暴露，不称盲测留出；新文件不等于新项目。
- 记录候选全集的筛选理由和淘汰理由。若 Codex 的真实补丁不足，不用仅有报告的文件凑配额。
- 十个困难文件是诊断/开发集，不足以估计真实用户总体准确率，且同项目文件相关。报告逐文件与逐项目结果，不把二十次重复当二十个独立文件。

## 给调查员的问题

只提供文件、原始会话池、生成结束锚点和观察结束锚点：

> 这个文件在生成结束后发生了后续修改。请自行查明改了什么、为什么要改，以及现有证据能否解释为什么生成阶段没有一次做对。不要假定每次修改都是生成错误；归因需给原始依据、反证和未知边界。

不给缺陷标题/数量、预期责任人、预设原因、关键关键词、参考摘要。源记录本身的历史报告保留，但必须与源码、调用回执和行为验证区分。两组共享语义任务；原始组不因缺 YAML、图坐标或工具专用引用而扣归因分。

## 参考答案不是标准散文

每文件包含：

- **修改账**：原始事件身份、use/result 位置、时间、实际内容变化、阶段，失败/条件/不透明效应单列；一条脚本可能有多个变化，多次修改也可能服务一个原因。
- **归因单元**：对一组有关修改，回答“为什么改”和“最早能定位的生成输入/实现/传递问题是什么，或为什么不属于已证生成错误”。按原因归并，不按工具版本号、补丁行数或预设问题数计分。
- **证据**：原始文件相对路径、物理行、块/字段、调用 id、摘录、行哈希；能证明什么、不能证明什么。
- **反证与界限**：竞争解释、未收录子代理/文件、无效截图、仅编译通过等。缺记录不能自动证明未读/没要求。
- **机制假设**：skill、编排、上下文等可能机制及需要怎样的干预才能验证；与已证局部责任分开。

机检只能证明引用定位、字段原文与事件配对；不能证明引用支持因果断言。语义审阅仍需核前后代码、输入、阶段、反证和验证记录。模型新发现参考遗漏时，先登记参考修订，对两组对称重评，旧参考与旧分数保留。

## 分数合同（跑前冻结，不再把清单分叫 ACC）

主报“**正确归因覆盖率**”：每个文件，正确解释的参考归因单元数 / 有界参考归因单元总数；再对十文件等权平均。必须同时回答该单元的修改原因与可证的生成期责任/非生成责任/未知边界，才能计为正确。不是逐字匹配，也不要求原文所有补丁数字都复述。

同时必须报：

1. **归因精确率**：被核实的实质因果主张 / 全部实质因果主张。无依据的新指控进入分母；同义复述只计一次。零主张为未作答，不记 100%。
2. **全文件通过率**：关键归因单元无遗漏且无实质错误归责的文件运行数 / 所有预定运行数；文件级两次结果分别展示。
3. 修改覆盖、未知/弃答、重大错误归责、引用可定位率，分开列。不用格式成功代替正确性，不用大量谨慎未知掩盖未查证。
4. 原始记录只支持“未知”的单元，正确说明竞争解释及证据界限可计正确；对证据足够的单元仅说未知计未完成，不作为错误指控。
5. 超时/无最终答案在端到端指标中保留为未完成，同时另列已完成条件下的结果；基础设施事故单列并保留产物，不静默丢弃失败跑。

关键归因单元、归并规则与重大错误条件在读取新原始组报告前冻结。缺乏明确裁决依据的争议单元不硬判因果真值；其参考内容是可证事实与未知界限。

成本记录实际输入（含缓存拆分）、输出（含推理口径）、总处理 token、墙钟耗时、串行交互轮次、实际返回字符及截断/失败重试。batch 内调用数不等于模型往返次数。质量不达标时，不将 token 下降叫提效成功。

## 实验隔离与审计

旧十二跑均出现宿主 skills 指令，至少两次原始组读取宿主 skill；不能照搬旧配置并声称隔离已解决。新跑前必须检查实际传给模型的指令、可用工具、环境版本与原生转录。冻结池与审阅资料分目录，模型不得读参考/实验答案/生产仓库；不能仅凭工作目录不同就声称操作系统级隔离。

全部原始命令只作为数据阅读，不执行历史命令。调查员允许正常批量检索和解析原始 JSONL，不刻意使原始组难用。禁止额外代理、互联网和参考材料，两组同样执行。实际工具返回的文本才算已交付；命令聚合日志、存在可展开入口和模型脑中理解不是同一回事。
