全部56单元：**正确32、部分完成8、未覆盖10、明确错误6**。部分完成不等于错误；说对一部分但遗漏其余，也不等于全文件通过。

两个覆盖率不同是因为每个文件的修改复杂度不同，**不是换算出两个互相矛盾的准确率**。只有1个核心单元的文件和有6个单元的文件，在文件等权指标里权重相同；单元等权则后者更重。两种都公开，不挑好看的一个。

“全文件核心通过”不认证报告的每一句辅助说法都正确。例如F10-10两跑识别了签名引用原因，但对早期删除/配置状态仍有过度推断；这些已进入主张精确率和裁决，不把核心覆盖冒充无瑕疵答案。引用能定位也不等于断言成立；本轮没有把不同格式引用的定位率混成归因分数。

## 这轮确认了什么

原始组不是一无是处：对明确阶段边界、真实读写和输入约束，它能给出正确原因。新一轮也再次说明，**找到一段合理解释不等于覆盖全部修改，覆盖核心原因不等于额外流程解释都属实**。

可重复核查的障碍包括：

1. 只解析原生Edit而漏Bash写入，或只查一个阶段；最后把不完整清单说成“只有这一组”。
2. 自写解析器的参数/编码错误、长JSONL截断和报告正文挤占修改证据。
3. 混淆池内存在与actor当时收到、后期快照与生成状态、worker报告与全池事实。
4. 局部代码原因已对，继续向上解释时却编出未证的编排/skill/职责原因。

逐步记录与对应设计验收见[失败诊断](raw-failures-v1.md)。这比先决定知识图谱应长什么样再寻找优势更有依据。

下一步优先统一原始取证、时间范围、修改对账、批量展开与自动轨迹记录，然后才用同条件工具组测是否纠正这些具体错误。若收益只来自稳定的JSON读取器，应如实承认；必要时做“通用读取器无图谱”消融。**现在既没有证明工具比raw更准，也没有证明省20–30%成本；不以UI或引用校验通过替代这两项。**

## 实验可信度与限制

- 10个不同文件来自0723、Dice、两份Codex rollout；不是预设10个缺陷，也不是20个独立项目。筛选先于本轮答案，困难开发集已暴露，不是留出集。
- 参考在跑前冻结，28核心单元/评分分母不变；支持材料不是逐条必须复述的检查表。实际模型/effort从20份原生turn_context核出，均为Luna medium；无自动重跑或模型回退。
- 参考与裁决由父/子审阅代理查原始代码、输入、回执、反证形成，**不是外部人工金标**。不能保证参考穷尽所有隐式改动或语义；真正改变答案的新证据必须登记并对称重评。
- 接受raw新增完整SDK枚举、后期签名/SDK快照差异，见[补证记录](baseline-v1-amendments.md)；没有为降低模型成绩事后增添必答内容。
- 原始新manifest哈希228份JSONL；208份既有sidecar另按先前完整pool-manifest补查。20跑结束后436文件全部hash未变、无新增文件；冻结题面、参考、运行器、配置校验通过。
- 338调用全部有唯一原生返回配对，无缺失/歧义和孤立返回；[范围审阅](raw-scope-audit-v1.md)未发现成功池外读取或执行历史命令。6次坏cwd均在创建进程前失败。**程序审阅不是OS级隔离证明。**
- 所有20跑无宿主skills目录注入记录。原始池仍保留历史报告/指令和敏感内容，这是调查数据，不能当宿主指令或声称全部已脱敏。
- 本轮64条相关实验基础设施测试通过（原62条复跑，加2条录制审计回归）；不是生产全套测试，也不是归因正确性证明。最终分数、成本及所列调用片段另经子审阅者只读交叉复算，没有改判。没有改生产MCP/UI，没有重跑真实迁移。
