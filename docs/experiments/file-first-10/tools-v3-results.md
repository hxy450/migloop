## 本版实际改了什么

主要修复时间重构后的信息呈现退化：file/agent默认重新给有时间界限的真实读写导航与原生正文入口，而不是只给按时间排序的原始记录前缀；完整原始索引与搜索仍在底层，未识别效应不删掉。

- 读写/候选/任务消息各自计数、分页，批量中的预算裁剪保留可执行续查。
- 文件操作能打开对应agent在请求前的输入范围；导航不是新读写边，结果返回时刻不当精确修改时刻。
- 原生Write正文存在与当前文件状态未知分开；调用回执、效应、作者分别呈现。
- 请求/结果独立截时，旧回执按旧视图认证；UI独立查询共享同一内核，不修改已保存调查。

这是包含多项兼容/预算/导航改动的整版实验，不是单因素消融，不能把收益独归于两原子、时间或某一句GUIDE。详见[概览设计](time-atom-overview.md)与[v3计划](tools-v3-plan.md)。

## 仍未解决的工具与综合问题

实际query-trace中472个batch子项：407次ok、45次error、20次deferred（v2为393/45/43）。ok可能只交付定位或前缀，不等于正文已读。候选/未决项仍不能算成已查全。

- changes仍有13次整项预算deferred；file有4次，diff有3次。元数据/封装与正文预算还没统一到完整外层响应。
- 两次大小写重复OR被拒；还有批量形状、scope冲突、累计blame继承修复下界等错误。有效安全拒绝不能直接取消，但应让正确调用更容易。
- Member两次仍漏mask和图像；价格只解释后修分段样式，没有补齐生成输入已存在但未落实的链。
- Dice Index两次已收到视觉修复新增console的差分，最终仍没讲清后续hilog之前的引入阶段。继续要求填事件id不能自动解决已读后漏写。
- Dice任务的前240字符可能不包含关键限制；可展开入口不等于原文被模型看到。应测试预算内原始输入/修改证据包，而不是预写个案答案。

冻结之后另修两项：[大小写重复OR幂等、同一源事件跨原子/changes/diff身份统一](post-v3-regressions.md)。它们有回归测试，但**没有注入本轮，不把本轮分数算成这些后续修复的效果**。
