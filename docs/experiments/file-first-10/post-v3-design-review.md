## 转录、回执与实际模型上下文：不能混为一层

六份运行共有49条 `response_item.custom_tool_call_output`；其中27条在文本前500字符内含 `Warning: truncated output`。分布为03 rep1 6/11、03 rep2 5/6、07 rep1 5/8、07 rep2 4/8、08 rep1 3/9、08 rep2 4/7。这是**保存的外层聚合文本的标记计数**，包含工具发现等返回；不是“27次内层 MCP 正文未送达”，也不是模型丢失证据比例。

需要区分三个可观察层次和一个不可直接观察层次：

1. MCP 执行事件保存的 `item.result.content[].text`：可以核服务器实际生成的正文、状态和回执。
2. exec 的 `custom_tool_call_output` 聚合文本：可以核该保存表示中的前缀、尾部、缺口及仍可读的原文片段。
3. 从上述记录投影的 query trace/receipt：可以证明某层保存的返回与请求、正文相匹配；不能仅凭列出 ref 认证相应全文被模型阅读。
4. 调查模型当轮最终上下文是否另行包含了内层结果、采用何种截断/压缩，以及实际注意到了哪些文字：本审阅没有逐 token 上下文快照，不能由聚合标记独立证明。

因此，“外层未出现某 ref”只证明它不在这份外层保存表示中；不证明模型任何通道都未收到。“外层可读到完整片段”证明该返回表示保留了材料，不证明模型理解或采纳。前述交付审计中的“已送达/未展开”应按已核可读返回与明确展开记录理解，不能升级成完整模型上下文认证。

## 提案一：有预算的原始证据包

沿用现有原子/查询，不添加gold专用检索词。对调查者已选中的少量操作，优先共同交付实际差分、原始请求/返回片段、状态和准确可用时间；对已有明确地址的短任务输入字段，在预算允许时直接展开完整字段。长输入及先前Read仍保留原序、独立作用域、准确未展开数量和可执行续读。先做同scope、同选择结果的呈现/展开，不按“看起来最像根因”挑输入。

统一投影应同时服务HTTP、MCP和batch；保留完整机器结构作为按需展开，但默认不要重复同值路径/查询/声明来挤掉正文。计量对象应包含实际渲染的响应及回执，不能只算data。调用者把多个返回再聚合进exec时仍可能截断，不能承诺后端单项预算能控制所有外层上下文。

反例与边界：首条消息可能只是协调信息；巨大thinking未必有用；任务中列出路径不证明它被读过；原始Read观察不认证当前状态。自动展开必须有硬预算并保留余项，不能全池无界扩读，不能补历史边、升候选为写者或让晚返回穿过截点。

成本与小验证：增加少量字段读取和正文token；离线重放原调用或合成短/长输入，比较完整字段交付量、重复封装量、续读可穷尽性和两层可读返回。纳入failed/pending/晚返回/无路径/超长任务等反例。不跑模型时只能证明交付改善，不能证明归因更准。

## 提案二：轻量主张与实际交付证据表、有界结论复核

减少模型重复填写路径、时间、原始地址和展示节点的负担。让模型写局部原因、初期原因或未知、机制假设和短证据ID；系统从已核调用自动填充定位表。传播关系若需展示，仍由模型明确主张，系统不能按查询顺序或ref归属制造边。

证据表分清“原始字段已返回／部分字段／仅导航／未展开”，并显示它依据的记录层次。对同一结论关联的多次实际差分并列展示，供一次有界复核；不把事件已挂到finding当作整段内容已解释，也不要求逐个hunk或全部ID复述。多个修改可以有一个共同解释，辅助遗漏不应被机制变成自动清零。

对“历史没有某输入/验证”的主张，复核首先核其论域是否超过已查询范围。超过时只标需限定或补查，不自动判假；已有构建成功也不能升级为全部运行行为证实。与之相反，明确的“本次未查到”不应被逼成否定历史。纯机械系统不能认证语义蕴含，相关提示必须保留semantic_checked=false。

反例与成本：轻量结构可能丢掉模型主动标出的关系区别；证据表重复全文会再次膨胀；额外语义复核可能强化原误读。先做确定性的表与轻量草稿，不优先添加第二模型或强制长自检。离线可核每条引用的层次/范围、未展开提示及原文字节，没有新模型时不声称能自动修复语义错误。未来若开展比较，应把复核轮次及token/time计入预算，使用不含这几个开发样本答案的规则。
