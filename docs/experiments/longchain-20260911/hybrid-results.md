# 保留原始读取、可选 MCP，以及后置呈现：实测结果

2026-09-11。沿用本目录已冻结的会员页文件级任务、六项归因判据、原始组报告和 MCP 代码包。新增一次 hybrid、一次条件触发的 post-hoc，均为 gpt-5.6-luna / medium，无重试，没有重新跑原始组。协议见 [hybrid-protocol.md](hybrid-protocol.md)，旧对照见 [results.md](results.md)。

结论：**本轮没有证明可选 MCP 提高归因正确性；后置结果能结构化加载，但语义保真不合格，不能作为可靠的归因裁判。** 不据此否定“保留原始读取 + 工具辅助”，也不把可加载图当成正确性提升。

## 1. 混合调查：与固定原始组同为 3/6，实际没用 MCP

| 固定归因项 | 原始组（不重跑） | 原工具组（不重跑） | 本次 raw + optional MCP |
|---|---|---|---|
| mask | omitted | omitted | omitted |
| images | correct | omitted | omitted |
| cta | correct | correct | correct |
| price | partial | wrong | partial |
| indicator | wrong | correct | correct |
| repair-compile | correct | partial | correct |
| 严格正确覆盖 | **3/6** | **2/6** | **3/6** |

这里是**一个被修文件内六项预先固定的局部归因判据**，不是六个文件、独立样本或产品总体 ACC。partial 不计正确；局部正确不豁免其他机制断言和引用错误。由本次开发者核原文，非独立盲评。

hybrid 实际执行 19 次 shell 命令、4 次失败、**0 次 MCP**。原始组是 24 次 shell，原工具组是 9 次 MCP（含 21 个 batch 子请求）。混合组比 raw 修正了 indicator 的局部解释，却漏掉 raw 已解释的 images；两组都漏 mask。

hybrid 能找到 converter 的任务、XML/spec 输入、初版 Write、报告及批收尾材料，也知道编译成功不等于视觉正确。它仍未检查 Slice8 实际输入与输出，却写出“最早偏离……而不是后续 Slice8 业务接线”。因此不能接受其全文件唯一进入点/完整机制归因。

price 的正证据仍是：Slice8 在源码读取结果 L24 中收到仅数字字号放大的实现，之后 L264 的目标文件 Write 仍保留整串 30 的实现。这既不能解释成“整个生成期没有收到这条规则”，也不能凭初版 converter 就排除后续生成作者的贡献。修改 skill 的建议不等于已经核到历史 skill 的致错机制。

### MCP 是否不可用？

运行前同配置 stdio 检查能列出 14 个工具并调用 guide；后置组使用相同配置实际调用了 11 次 MCP。因此本轮证据更符合“调查模型没有采用可选能力”，不能称为“工具已被实际使用却没有增益”，也不能把 token 降低归功于未使用的 MCP。

hybrid 保留原始任务字节前缀与普通报告形式，只追加可选 MCP 说明。相对 raw，配置只增加 MCP；相对 tools-only，还同时开放 shell 并取消 YAML 提交负担，不能把组间差异都归于某一个变化。

## 2. 冻结原始报告的后置核验/呈现

hybrid 未超过 raw 且未交付合格机制链，按预先协议触发一次后置实验。输入是**旧 raw 报告，不是 hybrid 报告或参考答案**。旧报告保留原样，后置输出单独落盘。

模型执行 11 次 MCP（guide 1、index 2、sessions 1、batch 2、changes 4、check 1），没有 shell 调用。结果为 migloop-verdict/3：

- schema 错误 0；12 个按 finding 区分的结论节点，并非 12 个不同实体。
- 4 条声明写边全部核回账本；没有交出 read/dispatch 长链。
- 13 个不同引用、29 次出现均能定位；账本身份匹配。
- 现有 probe API 返回 200，含 argument_graph；本轮没有做浏览器逐项视觉验收。

**以上只证明结构和关系可核，不证明原因正确。语义审查不通过：**

| 后置结论 | 原始证据/问题 | 判定 |
|---|---|---|
| 价格拆分被标 candidate_effect，因此是否执行未知 | fixer L592→593 有修改脚本、成功回执和打印内容；前一轮 L528→529 也有实际修改依据 | 把“解析器未认证”错误外推为“历史事实无法成立” |
| 两张图片只有候选，不能写成已发生修复 | fixer L233→234 有尺寸修改脚本与成功回执，raw 已定位 | 将原先有支持的事实降级；不是可靠反证 |
| L532 输入包含 `.color/.selectedColor/.left` API 补丁 | API 属性补丁在 L528；L532 添加相关常量 | 写边可核，但边上原因引用错位 |
| converter 实际写入、编译修复结果尚未建立 | converter L61→62；builder L24 报错、L32→35 修改、L37 编译成功，均在池内 | 本轮没查完，不等于原始材料没有；不能由此推翻原报告 |

不主张脚本成功回执能独立证明最终视觉正确；这里核的是具体修改及编译事件，不能把“未重做设备验收”与“修改是否发生”混为一谈。对于原报告声称 spec 明写左下等真正错误，后置组也没有给出有针对性的原文反证，而是大范围降级。

这次后置任务允许核验和重新结构化，**不是纯机械序列化**。失败说明第二个模型仍会误读工具置信标签、改写原结论，不能据此断言只做呈现的方案不可能。

## 4. 下一步边界：调查、主张、机械核验分开

1. 保留原始读取，MCP 是增补，不是材料访问的唯一入口。两原子可以继续作为索引和展示入口。
2. 原始报告/主张以内容哈希固定；后置绑定节点、原文范围和已核关系，不能悄悄改写它。新的语义异议单独记录，保留“原主张 → 反证 → 修订”历史。
3. 分清 `not_recognized_by_parser`、`not_checked`、`contradicted_by_evidence`。前两者不能当第三者；候选不自动升实线，也不能阻止查原文后补交依据。
4. 图上分别呈现实际调查轨迹、后置核验轨迹、历史关系和模型解释链。此次只可称后置解释/核验图，不能声称它就是 raw 当时的调查路线。
5. 下一次工具设计变化要解决实际失败：紧凑而完整的多写者/阶段索引、未决效应与正式修改并列、原文直接展开、提交时暴露遗漏输入和修改。不靠增加 YAML 字段或强迫长链来提高表面分数。
