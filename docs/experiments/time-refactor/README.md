# 时间查询重构：第一阶段

分支 `dev/time-evidence`，起点 `93f4ed1`。这一阶段改变**调查范围的定义**，不把历史版本号换个名字。
不修改冻结评测答案、旧运行产物，不调用模型，不声称提高了归因 ACC。

## 契约

- `agent(id, at=T)`：该 agent 所属原始转录里，已记录时间 ≤ T 的记录。解析不出动作不构成排除理由。
- `file(path, at=T)`：同一时间范围内，已索引到该文件的记录，以及原文中的同名文件提及。提及只提供入口，不证明读写。
- `search(agent/file, at=T)`：搜索上述完整范围，不搜索当前页面的摘要。全池模式也使用原始记录，不经过动作种类过滤。
- `record(ref, at=T)`：按源文件名身份、行号、原文摘要核回一条完整原始记录，分页展开。内容改变、源名称歧义、晚于截止都拒绝。
- 未知时间单独计数；显式展开仍在独立区，不混入截止前证据。坏 JSON 保留，UTF-8/文件读取失败披露源缺口。
- `latest` 表示全部已录有时刻证据，并不等于“当前磁盘精确状态”。相同时间不推断因果顺序。

“在 agent 的转录中”与“该 agent 原创/执行”“当时仍在上下文”“实际采纳”不等同。例如 Codex fork 可能复制父记录。
这里不恢复未记录或不可解读的内容。`raw_scan_complete` 只表示所登记文件扫描无读取缺口，不认证 session 池完备、文件关联完备或归因完备。

## 代码职责

| 部件 | 负责 | 不负责 |
|---|---|---|
| `AgentRec.sources` / `transcript_store.py` | 显式源归属、原文、地址、32 MiB 有界缓存 | 按解析成功与否决定是否有记录 |
| `temporal.py` | 时间选择、完整检索、分页、可选关系标签 | 推断因果、复用最近版本作读到的状态 |
| `temporal_state.py` / `filestory.py` | 截止前已返回效应的重放、原生/区间 diff、保守行来源 | 从最终账本剪一段当作历史状态 |
| `atom_queries.py` | HTTP JSON、HTTP 文本、MCP 共用选择逻辑 | 路线或模型主张 |
| `time_receipts.py` / `probe.py` | 系统生成查询回执，对齐实际输入/返回，保留时间轨迹 | 把先后查阅变成读写边 |
| `fixchain.html` | 时间证据面板、原文展开、记录的时间查询复查 | 把查看器展开计入模型访问 |

新的 `at` 模式不要求 `via`。旧 file/agent 显式 `v` 与旧引用仍走兼容路径；HTTP 无 `at` 的旧请求也保持原义。
同一个显式时间查询在两个传输面选出同样的记录；MCP 文本另外附运行时回执，不额外发送一份重复 structuredContent。
回执摘要认证请求和返回的一致性，不是密码学签名，也不认证模型原因的真假；原始工具来源仍由现有录制器核对。

## 两类时间不能混淆

读取请求发起于 10:09，结果返回于 10:15：10:10 查询只给请求，连由后来结果解析出的文件关系也不能提前展示。

不透明写于 10:00，10:20 才读回全文：10:10 的重放不使用这个全文。10:25 的查询可以展示已观测内容，但不能把观测者/区间里的写者当作确定引入者。
`Version.content_ts/content_seq` 记录内容何时、由哪个事件变得可见；版本时刻与内容可用时刻分开。
时间 diff 的 `since_ts` 按实际证据可用时刻筛选，不让 10:20 的观测因为封到了 10:00 版本而在窗口里消失。

候选写可能不立版本，但会使 `current_content` 变未知。未完成写、条件效应、重叠或同时间写也不会产生一个自信的“最后作者”。
没有创建证明的首见整篇覆盖，不直接算代码最初来源。原生补丁仍可通过原始调用查，不因为全文未知而丢弃。

## 已验证的实录反例

运行 `audit.py <冻结 member-center/case.json>`，仅读取 0723 的已有池：

- 146 个 agent；一次冷建账 16.185 秒（本机单次，不作为性能比较）。
- 原读取 `#17287`：发起 `2026-07-26T21:45:50.368Z`，返回 `.448Z`，结果在转录第 27 行；旧绑定是 `v14, certain=False`。
- 在这 80 毫秒窗口中间查询：结果行不可见；到返回时刻后可检索。
- 文件时间搜索扫描 33,591 条原始记录，`priceDigits` 命中 6 条，含修复者原始第 592 行那笔未形成独立版本的脚本。
- 无源读取缺口；查询回执能核回，不产生查阅因果边。
- 当时重放正文仍未知，blame 不再把这个读回强挂给 v14 作者。重放耗时 0.337 秒；一次 JSON 查询加一次重复文本查询合计 7.854 秒。

上述数字只认证入口/时间隔离/保守来源行为，**没有新的归因正确率、token 节省率或弱模型对照成绩**。
旧单词 search 同时修正：保留 `certain`、观察窗口与 proof；不确定读取不再提示“看该版本是谁写的”。

全量 Python 回归：**1,667 项通过**，45.83 秒；另通过本地 Chrome 的既有调查树浏览器回归及新增时间面板检查：
HTTP 查询保留上下界、原文展开不越截止、原文里的 HTML 作为文字、查看器展开不改变模型访问/节点/边；没有浏览器异常。
浏览器使用的是确定性 fixture，不是真实模型调查报告。该检查不证明新版时间节点主树已经迁移。
临时浏览器与 fixture 服务均在检查结束后关闭，不依赖常驻调试进程。
