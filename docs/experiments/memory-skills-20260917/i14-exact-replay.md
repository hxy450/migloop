## 仍无法宣称完全固定的因素

同名模型不是已固定的远端权重快照；新会话时间、随机输出、服务负载不可消除。旧实验没有完整 Python 包锁或当时 CLI 二进制哈希，不能仅凭版本号声称二进制和依赖全部历史一致。本轮两组使用相同的当前 Python 环境和 CLI，另保存 pip freeze、二进制哈希和实际消息；旧内核同场对照用于识别这些共同漂移。

并发最多二，可能共同受服务速率/缓存影响，耗时是本次观察而非稳定均值。固定六项核心解释标准不变；附加错断和机械状态另计。没有复跑原始组，也不把单文件外推为十文件准确率。

### 能得出的结论

1. 之前“只移植成新 skill 再跑”的 1/6，不能用于宣称当前内核已经失去 i14 的调查能力。恢复原指令/接口后，当前内核本次找回全部修改类别，核心提升到 5/6。
2. 旧内核同场也只有 5/6，未重现历史那次 6/6；不能把未重现的责任全推给当前代码。反过来，一次相同核心分也不能证明新旧质量等价，当前组附加事实错误仍在。
3. **代码层的成本问题不能排除**：本次当前内核查询更多、累计上下文更大。先前已测得相同 calls 返回由 19,831 字符增至 30,844，写者导航由开头移到末尾，这是可定位的展示差异；但本次仍非单个函数的因果消融，不据此认定它是唯一原因。
4. 这次做到了“可控的实验条件只换后端”，没有承诺随机模型输出或远端服务也能逐字复原。每组仅一次，不外推十文件成绩，不用于声称优于原始组。
