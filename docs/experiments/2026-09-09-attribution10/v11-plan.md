# V11：合并搜索、减少坐标重试，不降低证据要求

本轮是已暴露开发集上的处理，不是新的盲评。沿用 V10 的七文件、十问题、各两次和相同原始组14跑；同一数据池、共同任务、GPT-5.5 / medium / native / reference。顺序 C3、C2、Member、Dice、Splash、C1、C4，先rep1后rep2。冻结代码之后才启动，新目录 `formal-v11`，旧产物不修改。

## 处理与假设

- `q_any` 为2–8个字面量 OR；同一范围只扫描一遍来源字段、共用24条/20k正文字符预算。逐词报告命中、可见、未展示；未知内容、未知返回时刻、部分版本另列。保留旧单字面量 `q` 与 `/1` 搜索凭据，新增 `/2` 严格绑定 OR 参数和实际展示的导航目标。假设它能减少重复搜索及上下文重复；不把单次字符减少当整场 token 收益。
- file/agent 头部直接提供可复制的完整来处坐标。首次误填自身 via 时给明确重试方法，错误消息只列最近8个完整已打开坐标并报告余量。不自动打开、不接受虚构 via、不把搜索变成读写边。
- 结论检查附有界的进入点/实际侧证据效应版本对账，UI按原始字段展示。只在显式进入点的所有实际侧动作均属于同 agent 更早效应、且无锚点效应引用时发窄警告。混合作者、无效应事件、未显式列入 entry 等不能升级为确定错误；所有对账都不认证语义。V9 Splash 的混合引用并不满足该窄警告条件，不能宣称已自动识别其错误归因。

## 保持与验收

旧查询/搜索凭据仍能重放；OR 参数不偷偷改变旧 q 的匹配语义。新 OR 只接受明确时区的时间范围，不用调用时刻代替未知返回时刻。增加搜索能力改变了 builder 源指纹，因此新账本身份正常变化，旧报告必须使用自己的冻结源，不跳过身份验证。

全部计划重复计入成本，最终结构无效也计入且单列。主指标仍为完整 `input_total + output`；另报 uncached、端到端耗时、无效调用、实际 OR 使用率。成本分析不读参考答案。语义评分仍用冻结 rubric，另外记录错误断言和不受支持的节点归因。不得因为少答题或全写未知而宣称改善。

整体目标仍为省20–30% token、归因质量优于原始组、真实UI可复查的联合条件；开发集达标也不抵消已完成保留集上的成本和错误边界退步。最终应报告本轮实际结果，不预设成功。
