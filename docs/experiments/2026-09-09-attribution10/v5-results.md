## 真实回放发现的解析器缺陷

原调查源码 `5b770be` 的 `_tool_output` 对显式 `text/input_text` 正文再次解 JSON、序列化，改变了空格。原生记录与交付正文其实逐字相同，解析器却判不同，未剥离传输头，导致原 metrics 的两次核查均为 `unverifiable`。

后续单独冻结 `source-d14853c` 修复显式文本正文保真；仍按同 ID、同来源、同参数、完整配对及逐字正文核验，没有改成宽松 JSON 比较。旧单 result 包装只在原子坐标解释时处理，不修改记录正文；多字段或重复键不丢弃。新的 14 个用例覆盖 JSON 保真、字面 error/result 不冒充包装、完整原生 check 配对、正文被改仍拒绝。

原 run、metrics、旧查看器审计和失败态截图不改。新审计文件是 `audits-v5/*-viewer-d14853c.json`，明确调查源码与查看源码不同，账本身份相同。两跑最终 hash 均匹配最后一次真实 check；第一次诊断也仍可展开。这个 matched 只认证同稿，不认证原因，亦不是服务器签名。

## 运行后继续修正：action 自己提供了假版本入口

直接重读两份 V5 原生事件，发现这些错误不能全归给模型：C4 的 `action(#4622)` 响应写着“喂 v253 → agent(..., v=253)”，Member 的 `action(#26431)` 写着“喂 v6 → agent(..., v=6)”。实际主代理分别只有 252 / 5 个效应版本。这是 action 视图将收尾喂养槽误当可导航版本；此前只修了读者列表和搜索摘要，没有覆盖这里。

运行后修正 `action_links`：可导航 `ver/agent_v` 必须在真实效应范围内；另保留 `feeding_slot`、`n_versions`、`after_last_effect`。收尾原文仍可读、仍有事件 ID 和物理指针，不挪到最后一版，也不为零效应 agent 造 v1。写前/写间的读仍可导航到真实存在的下一效应版本。

Member 那个动作只给裸动作号和 `...:L54/0` 事件 ID，没有可复制的完整引用；模型确实拼出了不合法引用。action 新增独立“原文引用”行供直接复制，事件 ID 保留但明确不是引用格式；缺定位则明确未知，不拼造。这个修正没有进入 V5 调查，因此只能说修掉已复现的诱导入口，不能声称已量到减少改稿次数或成本。

## 下一步：针对剩余失误，不再单纯加提醒

1. 用同题重复验证上述 action 源头修正能否减少机械错误与整稿重写；预检继续作兜底，不让它掩盖工具自己的错误提示。
2. 让“当时输入”和“后置用于对照的正确要求”在节点依据中明确分开；窄窗口查过 Write 不等于查过该 agent 的早期输入。先用反例验收接口，再测模型是否补查，不用额外一段提示代替验收。
3. 保留有证据的已执行写入与未知最终快照两个独立状态；把底层执行、读取保存报告、直接行为观测分开，避免保守到丢掉成立事实，也避免摘要升级成验证。
4. 预检成本需要独立消融：尤其是完整草稿重复生成。可以研究只提交一次完整结论、再对已绑定文档做有凭据修订，但不能以“少抄一遍”为由丢失最终稿绑定或隐藏失败尝试。
5. 当前归因仍有遗漏；先补这些确定反例，再做同题重复与未见题。图画对和机检全绿不等于飞轮已证明能减少下一次迁移错误。
