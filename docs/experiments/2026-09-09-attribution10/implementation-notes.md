# 本轮实现边界

两原子仍保留。需要拆开的不是第三种业务节点，而是三种不同的关系：历史账本关系、调查者的导航、调查者的归因主张。

## 事实不因展示面而改变

- `file_ref_payload` 统一 agent 槽和 action 导航中的读取范围、依赖读、条件分支、版本确定性及观察窗口标签；UI/MCP 是同一事实的两种投影。
- 读的完成时刻表示此时结果可用，不一定是快照取样时刻。与写入/未知效应窗口重叠的读保留原文，但不封到旧写者、不制造“实录外回写”。复制源重叠写时也不拿旧源内容冒充已知目标内容。
- Codex 原生消息、显式 system/developer 输入、session_meta.base_instructions 可检索并展开；镜像记录不重复计数。收到的 reviewer 报告是可定位的消息主张，不制造缺失子代理的执行、文件写入或实际读取边。
- 原始 action 的输入/输出共享展示预算，能一起放下时不先截掉输入；放不下明确给出各侧分页入口。可展开不等于已经看过。

## 搜索发现不伪造历史因果

search 的实际返回为显示出的精确命中签发本次服务进程、账本、参数及正文摘要绑定的导航凭据。模型可以从该命中打开 spec，即使历史生成 agent 没有读过它。凭据是可核对的过程记录，不是对文本真实性的签名，也不是秘密或权限认证。

页面单独显示：确定的账本关系、不确定的候选关系、未核出关系的探索跳转。搜索仍是调用事件，不是第三种原子；重复访问仍逐步保留。只有声明 via 不足以证明一次打开成功，还需配对真实请求/返回、完成先后、精确版本和 MigLoop 工具来源。其他 MCP server 同名 `file/search` 不得认证为本工具访问。

结论节点的角色/原因是模型主张；引用有效只证明定位，账本读写边有效只证明有限关系。它们都不证明模型理解、设备行为或缺陷解释正确。

## 原文与账本的两个限度

“账本没有确定文件版本”和“原文不存在实际变化证据”不是一回事。模型应展开候选命令、结果和可用前后内容，给出有边界的语义判断；不能因为工具没有复原版本就放弃可核事项，也不能为了画图捏造版本。无可核文件版本时可落在真实打开的 agent@v，披露目标文件版本缺口。

“检索结果为零”和“信息不存在”也不同：时间范围、未记录子转录、未知版本、限额与截断必须保留。原文信息无法保证无损复原为读写图；保证的是不把已知不确定性抹掉，并提供可检索/展开的原始入口。本轮没有获得 Codex 两根缺失的全部子转录，也没有独立设备验证。

## 实验边界

18ca512 上的三次 GPT-5.5 试跑使用旧的泛化整文件任务，属于 pilot，不与后来增加了中性问题的任务直接算版本提升。新的正式题冻结问题、原文池、参考证据及源码；每次失败和格式错误保留。题库一旦用于改工具，就是开发回归集，不再称未见测试集。

单元测试和浏览器合同测试用于找机制错误；10 道历史题用于检查归因。两者分开报告，均不证明下一次真实迁移一定少犯错。
