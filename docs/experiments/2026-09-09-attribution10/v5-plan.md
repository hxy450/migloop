## 修改与假设

新增只读 check：在最终输出之前反馈格式、身份、坐标、引用、显式边、限定清单对账与缺失归因对照。不是语义评委，不读新原文，不打开节点或发导航凭据。返回原始文本 hash 与规范化文档 hash；只有真实配对、未截断、可信 MCP 返回与其输入对应，且最后一次核查文档与实际展示的最终 YAML 一致，页面才标 matched。matched 不等于没有告警，更不是原因正确。

node.basis 为向后兼容的可选字段：expected、actual、两侧 evidence、counterevidence；指南要求红节点提供对照，未知反证可明确写未查，不强迫编造。缺字段只是诊断，旧报告仍能加载；填齐也不使 semantic_checked 变真。UI 按缺陷展示原文及两侧证据，不自动改色。

假设：先核查再提交可减少错版本/引用；明确要求-输出差异可减少正确修复者或发现者被当错误来源。没有出现定位错误不算归因通过，仍按原文逐题裁决。新增关于 manifest 的证据等级说明也属于本次干预，因此不能将结果归于单独一个字段/工具。

## 验收及成本

- 机械：身份/引用/节点/显式边错误、草稿与最终稿匹配、未伪造访问/关系，告警不被绿色状态盖住。
- 语义：S3 实际执行与最终状态分开、例外完整；S4 正确输入到错误实现的责任链及 fixer 新错；C4 静态/后置构建/记录报告/独立设备核查/补丁绑定分开。全未知也不能偷过关键正向证据。
- 成本：headline 保留全部 token/time；另列 check 次数、所有 draft 字符、check 返回字符、最后状态与 final-match。不扣除预检开销。
