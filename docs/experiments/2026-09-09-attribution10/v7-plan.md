# V7：短入口与未知归属的续查，不削弱证据

在查看 V7 模型产物之前固定本计划。现有十题仍是开发集，新五题答案不提供给主线程调优或调查模型。

## 改动与假设

1. GUIDE 全文移入共享 guidance 模块，默认 core 短入口；evidence/search/investigation/navigation/verdict/full 按需展开。完整旧规则和 schema 保留，MCP 描述只列操作要点，HTTP 同 topic 逐字返回。假设减少每轮重复携带的早期上下文，同时不损失证据边界。
2. blame 无法逐行复原时返回 bounded recovery：截止前可靠原生全文写、复原断点、本版原生补丁、期间正式版本/未知效应/提及的分开计数及原文查询入口。它不生成内容、旧行作者或读写边。假设减少“blame 未知即停止”的可避免遗漏。
3. 未绑定版本的 conditional/read candidate 保留为路径级调查线索，不再投射到任意已查文件版本的读边。早期输入预览保留范围/不确定性；action 空末页明确 EOF。

这些是捆绑版本；不能把观察到的全部 token/语义变化归给某一项。显示层沿用已验证的独立布局组件与三层证据区分。

## 固定调查协议

- GPT-5.5 / medium / native MCP，1800 秒；工具组统一 reference 最终交付。完整 migloop-verdict/1 仍由模型提交 check 并原样落盘；最终小引用只消除重抄，绝不省略原因或 coverage。
- 使用既有 formal-v1 或 V6 case 的精确 common-task 和只读 pool，variant 新目录，不刷新题目、修改旧报告或追加参考提示。
- 先 Member 与 C4 各两跑诊断；同一冻结代码再跑其余五个文件任务各两跑，共七文件/十题/十四次工具调查。若中途必须改代码，另起版本重记，不能把不同代码拼成单一候选成绩。
- 原始组同 GPT-5.5 medium、相同任务和池，每文件两跑。已有 V6B 四跑满足相同模型/任务/池时可作为这两个文件的原始对照并显式注明其来源；其余十跑新录。原始组仍无 YAML/coverage 负担，额外审计交付成本属于工具组产品成本。
- 调查并发最多两跑；源码/runner 冻结并记录摘要。一次调用失败保留，不覆盖或悄悄重试。

## 判据

主成本为每次 input_total+output（缓存已含 input_total），另列 uncached+output、缓存及端到端秒数。分别给每题归一化平均和总量，不挑最好重复；预期总体节省20–30%，小样本结果仅是该集合观察。

语义回原始记录，沿用 reference-v1 的可回答事实、反证和时间边界；既计事实召回，也计错误/遗漏。错认作者、将不确定版本写成确定、后来要求提前归责、把报告当底层验证，均不能靠“引用有效”抵消。没有实际证据的正确猜测不计为已证实归因。全写未知不算答对可回答的事实。

报告逐项裁决，不将节点数量、coverage 交齐或 check 通过当语义分数。工具组优于原始组须同时保住可答事实、降低有实质影响的错误/遗漏；遇到一项提升另一项下降就披露权衡，不强判胜。

审计/展示验收：最终文档与真实 check/双哈希一致；保留全部调用和导航，不出现未绑定版本的读写边；节点原因逐字呈现，候选/已定位/模型主张区分；真实页面与浏览器回归均通过。

先验证开发集候选，再运行独立冻结五题的 holdout。没有通过就继续定位失败，不将其改名为已完成验收。
