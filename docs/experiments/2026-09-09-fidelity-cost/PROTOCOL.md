# 忠实性与提效：冻结配对试验

本轮目标是同时满足：调查路径忠实、主张不误绑、原文可回查；然后比较成本或事实质量。不是以节点数量、引用数量或调用深度代替准确率。

## 硬约束

- 每次成功/失败/未完成查询均保留；重复访问、回环、多来处不丢转移。
- 实体只有 agent@版本 / file@版本，访问窗口记录在步骤上。声明导航和账本关系分开，未查询的结论节点不叫“查过”。
- 模型、harness、当前账本身份明确冲突时，不把历史主张绑定到当前版本。
- 引用可定位、引用在模型返回中出现过、原文支持断言，是三个不同指标。
- 生成前关键词零命中仅是限定范围未检索到，不能据此认证需求不存在；后来首次观测到也不证明此前语义上不存在。

## 配对设计

初始开发集覆盖两类：DiceRoller EntryAbility（后续阶段加入能力，避免把阶段性需求变化归罪生成者）；0723 SplashPage（检查原需求与生成实现是否有具体落差）。再用 MemberCenterPage 做未参与首轮调参的检查。对案例性质的描述是选样假设，不是预先认证的金标。

- 同一冻结原始数据池、同一任务正文。按用户的生产模型要求，两组均使用 Codex `gpt-5.6-sol`、`medium`，不用 GPT-6 调查；由真实 rollout 的 turn_context 核对模型与档位，不能只信启动别名。
- raw 组可用只读 shell 的检索和 JSON 解析调查原始转录；tools 组禁用 shell，仅配置 migloop MCP。两组共同关闭网页、插件、其他代理、浏览器、记忆和用户规则；不修改用户全局配置或身份认证。
- 两组 `-C` 均为冻结 pool；Windows 显式使用本机已有的 elevated sandbox 实现，文件访问策略仍为 read-only。MCP 与 raw shell 均先通过实际执行预检，不能把环境阻断当作能力失败或工具优势。
- 两组均输出缺陷、生成前需求依据、生成行为、后续修改、来源变化、待确认项与管线建议，逐主张带引用。tools 组将这些内容直接填入可载入 YAML，不重复输出同一份散文。结构化输出及修复重试的开销计入成本。
- 每个案例至少做两次独立配对才报告稳定趋势；单次仅为 smoke / 开发反馈。运行顺序交替，保留原生事件与用量，不能把历史不同版本工具跑混成 treatment。
- 保留实际发送 prompt、CLI 参数、结果、模型调查转录、工具源码/数据清单身份、全部失败与 schema 修复尝试。不得只保留最好的一次。

## 量尺

成本：总 input、未缓存 input、cache creation、cache read、output（若含 thinking 不再重复加）、总美元、调查+重试墙钟、工具返回字符、拒绝/重复/未完成调用。Codex 的 input_tokens 已包含 cached_input_tokens，不能再相加；creation 依实际独立字段报告。订阅 CLI 未报告美元时为 unknown，不把目录价估计当实付。所有缺失字段标 unknown，不用 0。

质量：按独立事实/修复事项清单核重要遗漏、错误事实、无依据归因、时序越界、是否正确区分需求变化与生成错误。评委必须看到可核原文片段及来源，不只看两份报告。两组使用同一语义评分规则，引用字符串格式不同不扣质量分。

仅返回中出现坐标，叫“坐标曝光”，不叫“事实有依据”；原始组宽松文件名+数字匹配也只作线索。既有 basis_check.py 的 88%/99% 不直接作为准确率。

胜出判据（开发门槛，不宣称统计显著）：

1. 同等关键事项覆盖、无新增重要错误归因，配对总 input 或端到端时间至少降低 20%；或
2. 成本未改善，但重要遗漏/错误归因确实更少，且能指出是哪几条原文支持的改进。

任何硬约束失败、只因少查而便宜、只因引用更多而评分更高，均不算赢。出现回退就检查具体查询/断言，修改后重新冻结版本，再用留出的案例验证。

## 有限迭代

用户允许持续优化且未设总费用上限；每次调用设墙钟超时保护。Codex CLI 没有在本 runner 中硬执行轮数或美元限制，45 轮只是两组相同的任务提醒，配置明确记为未硬执行。完整记录超时、失败和重试开销。优先小批配对定位问题，不把同一案例反复跑出的印象包装为产品结论。
