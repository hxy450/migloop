# 下一轮假设登记（baseline运行期间不实施）

首对运行的失败不能直接归为“模型弱”。区分下列可验证机制；完整baseline评分后再排序，保持一次可解释的改动。

1. **覆盖契约奖励的是处置齐，不是调查齐。** `complement:not_investigated`让候选处置覆盖为100%，弱模型沿正式版本清单就停。应将已登记、已检查、已解释分为独立指标；保留诚实未知，但不展示为完成全部调查。检查候选是否有原文输出/脚本目标等高价值证据，优先可展开，不要求无差别读完几千命令。
2. **累积文件视图与精确via身份不一致。** 模型在file@v16内看早期diff，却只能拿v16当via；原始作者需要file@早期版本这一精确下游。它错误用sessions重试，然后改用search绕过。不要放行虚假的v16→原始作者读写边。可在一次file查询中展开历史版本的正文/diff，并返回可合法使用的历史版本via；UI将它们归在同一文件时间线内，读写边仍连具体版本。模型可不增加一次独立file调用，审计也不丢精确身份。
3. **快照时间被误作代码引入时间。** 会员页后来的priceDigits/priceSuffix被归到更早已有版本。应把“该事件实际写了什么”和“后来观察到的全文”明确分区，尤其在原生Edit之外出现候选写时。仅补时间参数不能修复这个状态语义问题。
4. **as_of作为视图边界，而不是事实推断器。** file/agent都可返回截止时刻前的观察、仍未结束的调用和候选效应。最近确定版本的内容与其后未知写区间同时返回；不能把两者压成“10:10确定读了v1”。发起、返回、缺时区及同时间并发分别处理。版本/原事件ID保留，不回填不存在的顺序。
5. **先证明读取契约可用，再要求深入。** 三次agent打开被拒后，模型没有利用已返回写者链或搜索凭据恢复合法打开。应核拒绝消息是否能直接给出有效查询形式；这属于可用性，不靠无限加“必须深入调查”的提示。也不能把search看到片段算成打开完整agent。
6. **批量展开可减延迟，但不是归因质量保证。** 当前file支持区间diff，模型仍连续调独立diff。可返回短的批量参数示例，并评估工具名/参数可发现性。未来batch action/file/agent必须逐项记录请求、实际返回范围、失败与via，不能用一个batch成功冒充全部成功。

原始组的反例也保留：Splash运行错误认定子目录为空，遗漏实际输入与补丁；会员页的原始坐标指向了不支持其结论的finding。优化目标是提高两组共同的事实与因果评分，而非让工具报告更像原始组。
