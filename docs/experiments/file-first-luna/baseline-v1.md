## 下一项查询设计判断（尚未实现）

保留文件@版/agent@版作为证据身份，增加独立的 `as_of` 查询范围，而非用时间替换一切ID。比如文件v1在10:00、读取发生10:10，应显示 `(v1时间, 10:10]` 内可能改变文件的动作，而不是截在10:00让它们隐身。明确区分调用发起、返回、效应不确定区间；边界内存在不透明写时内容可以保持未知，不能“选择最近版本”就宣布读取确定。

现有 `file(v=16,diff=True,v_from=1,v_to=16)` 已支持展开锚点内diff（分页40版）；旧全文仍通常需查询对应版本。下一轮可增加历史正文详情展开，将其记作同一文件视图里的证据访问，同时保留v9和v16的精确内容身份。展开旧详情不算新的因果跳转，也不制造file→file读写边。UI须同时保留调查轨迹与历史关系，两者不能混为一条边。
