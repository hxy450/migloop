## 已确定的方向

- 后续被测调查使用 `gpt-5.6-luna`，首个实验固定 `medium`；不因失败回退到强模型。若自动语义评审也调用模型，同样使用 Luna，但模型自评不能成为唯一真值来源。
- 两组只接收目标文件、相同原文池、阶段锚点和统一任务；不提供缺陷名称、问题数量、责任 agent、具体错误行或参考答案。
- 先保证自主找问题、归因正确、UI 忠实，再比较成本。不预设每次后续修改都是生成错误，也不强迫每项都归到某个 skill。
- 保留两原子。版本身份与时间范围的全面重构暂不作为开跑前提；先保留读取事件、候选区间、并发/截时回归和明确的未知边界。
- 不重跑真实迁移。本阶段只验历史归因、机制解释的证据和建议的可测试性；“下一次真的少犯错”仍是后续干预实验的问题。

## 核心缺口：建立文件级参考，而不是多跑已有小题

每个文件在运行前冻结以下评审材料，并与模型可读池隔离：

1. 生成锚点、调查截止事件、原始转录清单与哈希。时间不可靠或阶段不明时明确记录，不能推算一个方便的断点。
2. 范围内**修改事件清单**：已证实写入、候选效应、仅参与者主张分别记录；来自原始记录的独立复核，不能只抄工具自己的账本作为完备性真值。对无法识别目标的黑盒命令单列扫描缺口，不宣称全知。
3. **问题归并清单**：多个 diff 可属于一项问题，一次 diff 也可解决多个问题；格式/重命名/阶段接线不硬算缺陷。登记粒度及可接受合并拆分，不能按模型条目数量评分。
4. 每项的问题表现、适用要求、写前实际输入、引入/传播/修复事件、反证、未知和原始坐标。接受支持同一事实的等价证据，不强求参考中的唯一检索路线。
5. **机制层**：可确认的输入冲突/信息丢失/规则缺陷，与只能假设的注意遗漏/上下文负担分开。不把累计 input token 当作某一时刻的上下文长度；不把后来的 skill 版本当当时实际输入。
6. **优化层**：合理改进方向及可验收的测试边界，不设唯一建议措辞。记录干预对象、作用机制、旧错检出用例、回归风险；不能把测试计划写成效果已验证。

新发现反证时版本化修订参考；用新参考重评两组保存报告，不暗改旧分，也无需仅因改评分而重跑调查。旧十题仍作为定向回归保留。

## 分数拆开，不再只报 core 通过率

这是待在首跑前冻结的文件级评分设计，不追溯覆盖旧实验分数：

- **问题发现召回**：正确匹配的参考问题 / 范围内已核参考问题；文件等权和整体计数同时报告。候选/证据不足项另计，不冒充已证实缺陷。参考未覆盖的模型新发现先核原文，不自动判错。
- **归因正确性**：已正确恢复该项必答链的参考问题 / 全部参考问题；另列已发现问题中的条件通过率，避免只挑容易问题刷分。某项要求未知时，正确陈述有据的未知可通过，但不能漏掉原文里可恢复的必答事实。
- **机制证据**：已确认机制逐项核支持与反证；未知机制不强迫编造。将无证据的 skill/上下文解释作为事实断言，计实质错误，不因建议听起来合理加分。只有假设时不能报“机制已查明”。
- **建议可验收性**：每项建议分别核四个条件——具体干预位置、与已证问题的联系、旧错可检出的验收用例、适用范围/回归风险；可报满足项 / 适用项，不叫“优化有效率”。“加强注意/优化 skill/缩短上下文”本身不通过。
- **重大错误单列**：错作者、错时序、虚构读写、将报告当源码/运行事实、把阶段扩展当原始遗漏；不能被召回或节省 token 抵消。文件完整通过要求所有必答链通过且无实质性错误主张。
- **审计独立门槛**：调用与返回范围可回查，查询跳转与历史读写分开，候选不升级确定边，节点/事件身份真实，原因和假设原文保真。YAML/check 成功不认证语义；raw 无图坐标不扣语义分。
- **成本**：完整 input_total+output、uncached、cache、端到端时间，失败/修复重试全部保留；缓存不重复计，缺用量不补零。需要“效果可比”的同时报告，不能靠少发现问题省 token。金额只按真实可得用量和对应计费规则记录，不用单价乘粗略总量伪造账单。

机制和建议不存在完整金标的案例，应单列“机制未知但边界正确/建议可测试”，不能凑成统一的根因正确率。未来的局部干预重放或真实迁移结果另立实验，本轮不包含。

## 运行及优化顺序

1. 先完成 FF01/FF02/FF03 的文件级清单与隐藏参考，统一公开任务及语义评分。其余五例作为已选候选等待同样验收，不阻塞第一批；不把首批成绩说成全部八例。
2. 做最小 Luna 原始读取/MCP/最终交付连通性检查；核实际模型与 effort。遇额度或明确不可用立即停止队列，保留失败，不换模型，不改账号计费。
3. 首批两组各两重复：3 文件 × 2 组 × 2 次 = 12 次调查。原始组无提示的新任务和 Luna 都变化了，必须重新建立一次匹配基线；建立后冻结，后续工具版本复用。旧 GPT-5.5 原始组仅作历史参考，不参与新模型收益比。
4. 每轮先裁完所有交付报告再进入下一轮，不继续积累未评分版本。每个失败归类为材料缺失、检索/范围问题、证据误读、机制越界、输出/审计问题；一次改一个可解释的通用机制，保留旧结果。
5. 优先修已经实证反复失败的“快照作者当代码引入者”和“未核写前输入便停止”，再检验其他输入/skill/指令冲突、压缩记录是否可展开。不将这批案例答案写入 GUIDE。
6. 同步用真实最终 YAML 和录制调用回放 UI：原因落在正确节点/事件；机制假设另标、不变成历史边；查看页面时新开的内容不冒充调查时已读。扩展机制/建议字段前先定共享契约，不在正文上继续叠正则。
7. 三例稳定后扩至其余五例。已有八例均是开发样本；最终胜负需要另选未参与调优的新文件/新项目，不能把这八例重新命名为盲评。

暂缓：全量时间坐标改造、完整状态重放、源头快照系统、扩大模型并发、先做复杂知识图谱 UI。它们不是这轮开始验证的前置条件；只有实际失败证据显示必要时再纳入。
