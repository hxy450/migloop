## 哪些失败已核实

1. **未查候选被登记成“覆盖完成”。** Member首跑7个正式版本已解释、31候选未调查，coverage仍可complete。指标表达的是有无处置，不是查全或解释完。
2. **导航不顺，模型绕成碎片搜索。** Member首跑39次MCP中，成功原子打开只有两个file；三次agent打开全被via拒绝，随后靠search/diff归因。UI没有读写边并非漏画，而是这次查询没有建立可投影的读写路线。
3. **仍把晚期状态归给早期节点。** Member工具首跑把L592新增的priceDigits/priceSuffix归到更早v14/L528；Splash工具首跑把后期装配及modal错误归给初版converter，漏了entry-setup删除拦截和Slice11的错误解释。
4. **原始组也会漏查及错引。** Splash两跑均未利用足够的子代理原文，一次甚至声称子目录为空；Member重复引用L402证明其中没有的价格/指示器修复，第二跑把“没有改高度/安全区”扩大为“CTA未改”，遗漏L436横向padding补丁。
5. **找不到实际输入，就给不出正确机制。** 两组均未完整恢复Dice中通用allCaps映射与具体AC14“显示Roll”的冲突，也普遍遗漏后续独立replay。不能据此归纳为生成器纯疏忽，或说只能等待后期新增需求。
6. **交付协议脆弱。** Splash工具第二跑的draft_sha256少抄两个字符，最后稿引用被拒收。正确保留了身份边界，但协议给弱模型造成了不必要的长串抄写负担。
7. **坐标真实不代表关联正确。** Dice首跑把uppercase的v4归给形状缺陷B；Member第二跑把每个v10-v16都挂上全部四条缺陷。格式/check通过不认证这种语义关联。

## UI验收结果

五份有效YAML都用冻结服务/模板实际载入浏览器，检查通过：所有应显示实体、读写边的方向/确定性/步骤、独立导航时间线、结构化原因点击显示、无节点重叠和浏览器异常。失败提交另做payload审计：submission=rejected，defects/roles/findings均为0，没有把未认证稿涂到节点上。

这只证明**忠实呈现记录与模型主张**。主张仍可能错误，图也可能因为没有实际读写路线而是若干孤点。不能把“5/5可载入”当作归因正确率或调查深度。

截图及审计日志在产物根的`browser/`；临时Chrome和HTTP服务已按创建PID关闭，未动用户已有服务。131条既有时间/提交/轨迹回归通过，16条新增评测基础设施测试通过。

## 下一轮排序

1. 统一累积文件视图、历史详情与合法via：打开v16可以在同一查询展开v9内容/diff，并沿**v9真实写者**继续，不造v16→旧作者边；保留精确版本证据身份。
2. 增加独立as_of范围，显示最近确定版本之后、截止时刻之前的候选效应/未返回调用；明确观测时间与内容成立时间。不能仅选择最近v就宣称当时内容确定。
3. 把登记覆盖、证据实际交付、解释覆盖分开，给候选提供短而可展开的高价值入口；不靠一段“必须查全”要求补救。
4. 简化结构化交付：模型表达节点/事件主张，服务器负责不可变标识与最终提交封装，避免反复手抄长哈希和所有候选。身份校验保留，不自动猜测错引用。
5. 再针对写前输入与首次引入事件做工具侧披露改进；不能把后来观察到的快照作者当作代码引入者。详见[next-round-hypotheses.md](next-round-hypotheses.md)。

本轮没有修改生产工具行为，没有重跑迁移，也没有证明建议能让下一次迁移少返修。原始组从此冻结；工具迭代复用这些结果，不重复花费跑raw。其余五个候选仍需同样建立参考，不冒称已测完八个文件。
