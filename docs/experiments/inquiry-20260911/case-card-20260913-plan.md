# 情景卡制作：固定十文件重跑

2026-09-13，实施前确定验收。用户要求 skill + 随附审核脚本制作可加载案例卡，模型在形成原因链时复核自己的判断；重跑既有十个文件。

## 范围与不变项

- 仍为 F10-01 至 F10-10，来自 0723、Dice Roller、Codex 三次迁移；沿用 baseline-v1 的材料池、目标文件、生成截止和观察截止。
- gpt-5.6-luna / high，每文件一次，最多两个并行调查员进程；单例 1800 秒，不自动补跑、不中途给答案。原始组不重跑。
- 短任务只要求使用同一技能制作 investigation.json 指定文件的情景卡。配置只含范围和运行依赖，取消此前 Guide 单跑的特殊 review_start 提示。
- 每题独立工作区和 SQLite，避免查询其它题的报告。保留原始读取能力，不限制调查路线，不强制 via。
- 这是反复使用过的开发集，不宣称新的盲测或泛化证明，也不是只改变 skill 一个变量的因果实验。

## 本轮改变

1. 复用 inquiry/1 作为案例卡：实际修改、节点原因、证据链、未知与改进建议。无需新 schema、图引擎或页面。
2. 技能明确在形成卡片时反查「具体信息怎样从问题节点到达被修文件」，并核相反证据和正确输入边界，不仅检查存在某条读写路径。
3. 随附 check_card.py 调用页面使用的 load_report。核目标范围、原文、节点/边、路径、修改差集及基本交付字段；不修稿、不改索引、不执行模型。
4. 模型 submit 后自行执行脚本并看 review，最多三轮提交/审核。真实缺口可以交 draft，不允许通过删难点、改窗口或发明边达标。
5. 原 UI 的已存结论详情补上已有 unknown/hypothesis/recommendation/unexplained，默认折叠，不重做树或加入第二套卡片页面。

## 验收分别报告，不能合并成一个「正确率」

- 运行完成：原生转录完整、指定模型与 effort、技能实际呈现、同一调查员原稿。
- 机器核验：schema/源引用/时间/节点/历史边；loadable 仅代表同一服务端加载器接受，另做浏览器验证。
- 卡片完整性：修改已对账、未决项明确、问题节点路径状态、节点原因/原文/建议存在。draft 仍可加载，但不能冒充完成。
- 浏览器：十份实际报告逐份加载；节点原因与建议可见，无 JS 错误；保留原手动探索测试。没有生成报告的题计为无卡，不能用人工代写补齐。
- 历史归因：沿用原 28 个核心核对点并列逐文件结果；另记上游输入边界与机制主张是否有据，特别是 Guide 的已人工取证上游/交接/检查问题。不把路径连通当成归因正确。
- 成本：各题总时长/token、工具执行时间、压缩时间及未分类时间可分则分；保留超时/失败成本。此次不验证新 skill 是否改善下一次真正迁移。

先跑脚本反例与现有 inquiry 回归、原 UI 浏览器契约，再冻结整批实现。批次开始后不修改冻结工具/技能/题目、不筛选重跑，不把审核后的人工解释计作模型的答案。

技能包装方式参考 [OpenAI Docs](https://learn.chatgpt.com/docs/build-skills)；其结构验证不能代替上述行为验收。
