# i18：回执对象与时间诊断，不更改归因答案

i17 两个预定难例仍为9/11，成本上升。会员页把 HomePage 命令的返回当作目标读回；生成期正常接线放入 finding.changes 时，错误却只说“node time range”，导致调查员反复改节点截止。两者是可复现的产品呈现问题，另两个核心历史遗漏仍是未解决的调查失败。

本轮范围：

- open 及其续帧附原生 request_context，UI显示同一内容；原始请求可完整展开。命令预览限400字符并标出原始长度/截断，不解读脚本、不新增读写边。
- 导入时持久化唯一、时间有序的请求块/返回块配对（index/5）。行级 pairs 继续只作相关导航，不能拿同记录另一成功调用给歧义块背书。缺ID、歧义、反序、未知时间不配对。旧索引用原冻结代码，不原地迁移；重建须新路径。
- 展开回执时重新核请求原始字节，改变/缺失则明确不可用。时间上下文不冒充当前区间内的新事件。
- 时间错误给出 scope_kind、实际时刻、要求的上下界；finding.changes 对应目标修改窗口，生成期证据可在正确的节点/原因中引用。规则不放宽，不自动改稿。
- 独立代码审查发现显式边的附加引用漏核两端since交集。补齐校验；有失效/窗口外引文的边保持未核状态，不用其余有效引用掩盖。唯一早期例外是绑定操作的原生request：窗口前发起、窗口内返回仍是有效关系，request仅作配对上下文；既有回归守住该语义。普通UI查询同时清空旧原文及其配对命令。
- GUIDE只加通用“先核回执对应对象”的用法，不喂会员页、Splash答案。

预先决定试验顺序：先一跑会员页（gpt-5.6-luna high，固定任务/1800秒、不自动重试），检查6项核心、错误对象归责、主张证据、机械关系与成本。未达6/6或有重大无据归责/证据对象错误则保留失败，不跑其余9项。通过后再跑Splash与其它8项；全部同一冻结候选仍按iteration-plan.md的10文件/28核心和四文件重复验收，不把单文件成功视作整体达标。

没有重跑原始组，没有调gold，没有新增题，没有由第二模型改调查报告。UI诊断重载旧报告只检验展示与定位，报告正文/SHA及历史关系必须保持；不算模型纠错或新准确率。测试集反复调优，不外推总体泛化。
