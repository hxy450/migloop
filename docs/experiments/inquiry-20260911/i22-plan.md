# i22：先看匹配分布，再展开原始事件

i21 两题核心4/4，但 F10-04 又将较早的“尚未真机验证”延伸为截至观察结束不存在回执。独立审查确认重大额外错误1；停止剩余八题，不改原稿、不重跑 raw。

实际交付原因：搜索已匹配真正登录回执，却在正文39415字符处，模型没有续读到。它完整打开的是旧声明。只倒序也不够：真实回执由第86/156条变为第71/156条。因此不以“多一个order开关”宣称问题解决。

通用实现，不含case名字/固定答案词：

1. 全池 search 的原始匹配列表不变，先给完整匹配集的actor分布前四项（按命中数排序）、时间跨度及每actor最新匹配样例；可用group_by:agent分页看所有组。命中属于记录的actor，不认证读写者、验证或因果。
2. 每组给同时间、同关键词、同视图的可执行收窄查询。returns导航显式newest，未知身份不给伪造查询。普通记录/返回的旧默认顺序保留；records/returns/messages可显式oldest/newest，其余视图拒绝order。未知时间仍独立可选、排在有时刻数据之后。
3. MCP首批文本和UI共用查询结果；分组入口放原始命中列表之前，手动查阅不污染原调查、不给图新连边。
4. 真正测到的性能问题一起修：新建索引时增加pairs(b,a)反向索引。结果→请求查找无需对每个返回重扫全部早期records。只增加物理索引，不改变事件/关系语义；旧冻结SQLite不迁移。
