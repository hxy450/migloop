# 单次调查：初稿与机械反馈后终稿

用户最终裁定：一个 agent，只拿新 skill，一次跑完。原始／工具是我们事后区分稿件的标签，不启动两个独立调查，不拆两个模型轮次，不 fork/resume，不把评审答案反馈给调查员。

## 本次 pilot

- F10-01 MemberCenterPage，原有 pool 和生成／观察窗口；复制到新独立输入目录，逐源文件 hash 核对。旧九文件双臂队列维持暂停。
- 单个 fresh gpt-5.6-luna/high，1800 秒上限，原始或 MCP 自由调查，无额外反馈消息、无自动重跑。仅部署 `migloop-case-card`，不叠旧调查 skill。
- 任务仅一句：`使用 $migloop-case-card，为 investigation.json 指定的被修文件制作归因卡。` 新 skill、现有 MCP GUIDE 与接口说明均在运行前冻结；不改校验器、收集器、UI，也不注入具体缺陷／责任方提示。
- 第一次真实 submit 的原生输入是初稿，包括 schema 无效、未存入报告表的尝试；不能挑第一个成功保存稿冒充初稿。最后实际提交另存，中间稿和反馈全部保留。
- 四步反馈流程：定位依赖该边的归因 → 核必要事实 → 保留／改责／降级／撤回 → 同步节点、连接、总结、建议。已有原文可复用；只记录实际行为，不以是否重复查询替代语义判分。

## 判分与归因改进

沿用本轮之前封存的 `product-pair-member-reference.md` 六家族及边界，不因新输出更改答案。每稿逐项成立／部分／错误／遗漏，返修新生与生成责任分开。自动附证支持已经提出的判断；不得替任一稿补写关键归因。

除完成数，列出错误归责纠正、正确归因被改坏、证据补齐、仅坐标/挂接改善、未决保留、删掉但未真正解决的错误。复核动作与反馈的关联须用真实调用/稿件依据说明；不把同时发生的改动一律宣称由检查导致。

分别统计首提交前和反馈后时间/输入/缓存/输出（录制允许的精度），总成本沿用原生计数，不把累计缓存重复相加。机械可加载与语义正确分别报告。

这是同一产品流程的校验前后比较。初稿已经读到同一 skill，并知道随后会核验，可能也主动使用 MCP；所以不能称“完全无指导、无工具原始组”，也不能单凭前后变化排除额外思考时间的影响。

## 用户追加：直接原始取证的单次运行

第一轮仍在调查、尚未提交初稿时，用户要求再起一轮“不用 MCP，直接看原始材料”。执行前已明确理解为调查不走 MCP，最终提交及机械反馈仍保留。

- 自由轮：`_migloop-case-card-20260915/member-v1`；追加轮：`member-direct-v1`。两轮各自 fresh、一次跑完、相同 Luna/high、新 skill、内核、池内容及时间窗口；最多两个模型并行，不恢复旧九文件任务。
- 追加轮只向模型暴露 MCP `submit/page`，不暴露 `investigate`。page 仅续读提交反馈；调查直接读原始材料，也不直接查询索引数据库。工具允许列表依据官方配置的 `mcp_servers.<id>.enabled_tools`。
- 为避免修改正在运行的冻结启动器，追加轮复用 `RAW.launch`，不改生产代码或首轮依赖。`direct-mode.json` 封存实际使用的 `direct-task.json`、`direct-settings.json` 与专用编排脚本哈希；原 prepare 的 prompt/settings 只是未使用的基础产物，不冒充实际输入。
- 追加要求只限定材料入口，不提供任何案例答案、错误提示或评委反馈。实际读取、首稿和后续修订另行审计，不凭配置推定合规。

这也是同一 skill 工作流的校验前后比较，不是“两位模型共享同一初稿”。跨两轮仅比较实际调查方式和产物差异，不能把随机性或额外推理预算排除在外。
