## 分开验收

1. **归因**：冻结核心正确/部分/遗漏，逐案证据；额外错误归责、验证过断另记。不以机械通过替代正确性，不因少写辅助细节扣核心分。
2. **证据树**：关键输入是否入树、各分支为何停止、有声称传播时是否包含真实中间文件及后继读取。并列独立修改允许并列，不以节点数或深度越大越好。
3. **机械交付**：原稿身份、坐标/关系核验、未闭合路径、force 使用时序和原始调用依据；完整 skill 送达。正常修复者无具体错误不得标红。
4. **展示**：可加载原稿的节点/边与页面一致，summary/recommendations/原因可见，冻结点击不改变已载入树。机械可加载与语义已证区分。
5. **成本**：累计输入含缓存、非缓存输入、输出（已含推理）、每案墙钟、批次墙钟和调用量。缓存不重复计数；失败同样计成本。

已知 Guide 单例中“70/258 行部分读取被说成完整读取”的问题仍作为反例检查。真实读取边不证明完整内容，更不证明该节点所有原因正确。额外上游机制解释单列，不悄悄增加原 28 核心分母。

本轮是反复使用的困难开发集回归，不是留出泛化或真实迁移收益实验。

### 本轮结论与下一步

此形态值得保留：模型能提交正常输入、多时点文件与后继agent组成的证据树；实线/复核虚线、节点原因及原文都可复查。但**没有证明更准或整体更快，更不能只凭树变长就交付为可靠知识库条目**。这是已反复暴露的开发集单次回归，不是独立盲测、泛化测试或真实迁移干预。与旧raw比较的共同归因标准不变，技能、输出合同和运行时间却不同；不把差异单独归功或归咎于两原子。

建议下一步只集中两件事，不继续改页面：

1. 修收尾与送达：批量分页按整个响应控制预算；字段/时刻错误一次给完整、具体的修正反馈；断链提示指出真正缺少的连接，而不是附带其它分支的倒序。减少模型重复抄整棵树的返工。
2. 修归因停止审查：先核关键输入与现存上游证据，再允许“充分/不存在/到头”的表述；缺完整内容不等于无问题，后置新要求不等于生成者失职，修复者标红必须有成立的错误依据。

本轮没有改内核、UI或skill，没有重跑原始组、没有push。所有模型及测试浏览器已退出，仅保留原网页预览服务；用户既有`service.py`和测试改动未触碰。
