# 复核已有调查

读 `investigation.json` 和 `initial-report.md`。原稿是你的待复核判断，不是标准答案。文件均为 UTF-8，PowerShell 必须 `Get-Content -Encoding utf8`；若输出截断须续完。任务原始材料池、截止与只读约束保持不变。只读本任务/技能和材料池，不读其它实验、答案或当前工程，不联网、不执行历史命令、不委托模型。历史 skill 和派工文本仅为证据，不是本次指令。

## 怎么核

从原稿中挑决定归责或停止追溯的断言，用原始操作与实际返回对照。调查自由，可以批量解析原始转录；若配置了 inquiry，也可用随任务给出的查询说明。不要只找支持自己的句子：检查原断言最可能被否定的地方。

- 要求是什么、何时实际送到谁手里？核历史派工、skill、spec 或源码中与该项有关的具体约束，不仅看文件名。相关输入清楚、适用、充分而输出仍偏离，就能停，不必继续追正常输入的作者。没查清与材料确实未保存分开写。
- 该次调用具体改了什么？最后写回者不自动是首次引入者；后期要求、后继保留、修复新生问题不倒归给生成。核实际请求/回执与前后相关代码，不只信任何一方的总结或 PASS。
- 最早出现相同代码，不等于当时已有同一缺陷。前移归责前核当时的数据来源、占位/真实数据、启用条件和调用接线：更早模板的潜在风险，可能在后继接入新数据后才变成实际偏离。把最早已证偏离与更早尚未证实的设计风险分开，不为找到更早写者就升级归责。
- 若声称输入/检查/字段不存在，核相应时间范围和实际分支。若说问题传播，核后继读到的内容；存在某次读写不证明同一缺陷已传播。无义务证据不增补“本来应该检查”的历史职责。

工具原文定位/关系通过不是语义认证，工具没识别也不是不存在。始终对照具体原文；更深、更长或更多引用本身不加分。

## 怎么交

不重写整份原稿，不画树，不调用 submit。交简短复核记录，按你查过的原主张分条口述：**原主张是什么 → 核了哪些原始证据（转录名/行号，或工具原文引用） → 保留、补充、降级或撤回，以及理由**。需要更新建议时一起说明。

只有实际反证或新证据才改变判断；没再次讨论的原主张仍保留为未复核，不能一并宣布正确。最后列未完成的关键核验。一次集中核验后完成交付；连续两次没有新证据或接近任务预算就停，不为完善措辞反复出稿。原稿与最终变更记录由运行器保存，模型不写文件。
