# i20 成本诊断（不是新模型实验）

独立 Luna high 只读分析 i14-high / i20-high 的 metrics、query-trace、delivery-audit；主流程核对 i20 十文件合计为 46,281,905 input+output、43,748,608 cached input、6,035.68 秒。不重复计算缓存，不把转录字节数当 token，不重跑 raw。

| 文件 | i14 → i20 查询项 / open | input total | 主要观察 |
| --- | --- | --- | --- |
| Member | 124→107 / 90→63 | 7.001M→6.658M | token 实际下降；不能把所有文件描述成变贵 |
| Splash | 94→160 / 62→139 | 6.382M→7.656M | 独立打开引用 48→102，输出 28,512→38,775；展开证据明显增多 |
| Dice Index | 58→70 / 30→51 | 3.216M→4.811M | 独立打开引用 28→45，review 1→5，submit 1→2 |

i20 通用指南相对 i14 每题增加同样的 3,768 bytes / 11 行，包含反证、复核、原文和时间规范，不是个案提示。它增加固定上下文；更频繁的往返也反复处理已有上下文，不能把 cached input 简单称为新证据。

Member / Splash 冷启动与暖运行差额约 21.3→20.3 秒，Dice 约 1.7 秒，因此没有证据把主要模型耗时增量归咎于重建索引。这个测量不能排除各次查询、服务传输或宿主截断的代价。delivery audit 的 errors=[] 只表示审计成功，并不表示每帧都完整到达；不完整帧和 wrapper 截断仍按各份审计保留。

后续优化优先量化重复元信息、原稿重提和分页往返，不删除必要的输入/原文证据，不用降低查看量换取表面更便宜。i21 试跑期间不改冻结代码。i20 与 i21 十题原始任务段完全相同、raw manifest / effort / driver 相同；变化在通用 GUIDE 与查询实现。
