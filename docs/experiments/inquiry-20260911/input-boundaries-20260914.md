## 本轮交付判据

- 逐项复核 summary/reason 所依赖的关键历史输入。实际交付的 spec、skill、源码等如果用来证明充分/缺漏/冲突或停止上溯，必须有文件/agent 时间节点与可核交付关系；仅文字提及不算入树。不是规定输入数量，也不要求画全部读取。
- 每个关键输入分支分别有停止说明：相关要求正常充分，或更上游形成记录确实不可得。证据到头不等于正常；未打开或预算耗尽不是没有记录。正常和未知/有错的输入可以共存，不能用一项正常代替其它项。
- 用作传播依据的中间文件和后继读取必须保留在链上。先读后写可连接到同一个涵盖写完成的 agent 截止；不将读取/写入各自建一个断开的 agent 后，靠删除真实输入得到可加载稿。
- 节点/普通边/force 仍使用原机械检查。检查通过只证明已声明的源、时间和连接，不认证输入充分或关键分支齐全；这两项独立审原文和模型报告，不用原因关键词正则冒充语义校验。
- 基础原因、首次引入与后继保留、已有检查的边界，仍按 [原 GuidePage 判据](skill-guide-20260913-plan.md) 审核；不能因为树更大或输入更多就报正确。既有已知材料用于本地评审，不给调查员。

记录实际完整 skill 送达、各稿保留/删除的输入、可见节点/边、错误主张、调用与输入/缓存/输出/时间；不将机械 ready_for_review 当归因 ACC。
