# 原始组提升到 high：与 i20 同题、同深度对照

2026-09-12。十个固定被修文件全部完成，各一次，不重跑挑优。结论：**工具组仍有较高的归因覆盖、较少的重大错断，但优势远小于此前 medium/high 混比；总 token 和平均调查时间没有节省。**

新原始组运行器提交 `3af7096`；工具对照固定为完整 `i20-high`，未拼入 i21–24 的好答案。原始组10份 native turn_context 均为 Luna/high，转录完整，最终消息与报告逐字核回；工具组10份原稿 hash、最终 report_id 和 source_sha256 核回。完整池、题目、配置、CLI 与运行器冻结校验通过，没有改模型原稿、参考答案或生产工具。见[预登记](raw-high-plan.md)、[身份与成本审计](raw-high-audit.json)。

## 六条额外错断到底是什么

逐条原句、报告 hash、原始反证及审阅纠正记录在[最终裁决 JSON](raw-high-scores.json)。这里仅概括：

1. **Member：把机制猜测写成事实。** 报告称“medium confidence 规则造成了过度保守”，还说生成者没把 XML 明确宽度视为可用尺寸；但初始 C 和后续 Slice8 都已写入宽度280/254。缺比例/高度不能证明是 D-008 造成。价格本身解释了分段，却没有在最终报告里建立生成者收到富文本源码再写出统一样式的证据链，因此该核心为 partial。
2. **CC Entry：抹去实际修后登录验证。** 报告称记录只证明编译和静态正则；原始子代理 `c657f0879a83d117:184/187/190` 有后期真实 HMOS 手机号、验证码、登录成功。工具组也有同类错误，同样计1条。
3. **F003：把预计暴露写成已经实际暴露。** 报告称手机号校验修好后 androidId 阻塞“才被实际暴露”；相邻原文是“仍可能”遇到、静态检查，随后还明确两个修复未经过真机验证。能证明修复顺序，不能补出中间一次新运行失败。
4. **Dice Entry：把修改者没编译推成全池没编译。** observer 修改者确实不运行构建；另一个 builder 随后有真实 CompileArkTS、BUILD_SUCCESSFUL 与0 errors。仍不能由构建成功认证 observer 回调行为。
5. **Dice AppScope：同样漏掉独立 builder。** builder 21:23先读到新 bundle/vendor/layered_image，再构建成功；因此“不能声称已重新编译”的判断不成立。图标视觉收益仍可未知。
6. **Codex Dialog：把后期快照倒推成已证生成阶段引入。** 局部 Block→Default 原因正确，但报告断言已定位“生成实现阶段”。两根 rollout 缺创建 patch/子线程正文，含 Block 的直接快照在生成截止之后；中间未记录写入不能证明截止状态。这里判的是**未证阶段被当成事实**，并不是声称 Block 实际一定由后期引入。

审阅由开发者查原文并结合Luna复核，不是外部人工金标或完整双盲裁决。审阅也会犯错：本轮纠正了 Member 评委替报告补输入证据、把 HomePage 的行号当 Member、Splash 有界“能定位到”被误读成穷尽声明，以及 Codex 的“没记录写入＝没写过”推断。保留这些纠正，不覆盖模型文本。若将最后一条 Codex 阶段过断仅作置信度告警，原始组全文件通过为4/10、重大错断5条；两个核心覆盖分不变。主表仍按冻结的“责任阶段不得无据写成事实”标准计分。

原始组额外发现了签名配置前后快照中 `signingConfigs` 出现、compatible SDK变化等真实辅助事实，保留认可，不因不在参考概要里判错，也不临时增加核心分母。未穷尽主张精确率，不能声称所有其它句子都已独立认证。

## 这次如何改变我们的判断

- 之前原始 medium 对工具 high 的文件等权差值约24.2个百分点，**不能再作为同深度工具收益**；现在同题 high 的观测差值是3.7个百分点。旧medium还含Member题干和重复数差异，不能把缩小的分差全部归因于effort。
- 本轮工具的收益主要是覆盖和较少的无据确定性断言，不是“原始模型不会调查”。原始 high 已能解释多数局部原因。
- 原始调查的实录显示可修复的检索失误：Dice Index多次只枚举根目录 JSONL、遗漏嵌套子代理，最后错误声称独立 Edit不存在；两个后修文件漏掉独立 builder。完整池索引、按时间查询和跨代理证据导航有针对性，但这不是某个组件独立收益的消融证明。
- 工具也未达验收：仍有一条重大错误；完整问题节点到目标修复的时间/内容传播闭链尚未强制核验。本次没有实现或重新验收UI。
- 这10文件来自三个反复调优的开发池，每组各一次，不是同期随机对照。不能据此宣称稳定优于原始、泛化已证、skill优化已产生迁移收益，或工具已“尽善尽美”。

后续以这份原始 high 为固定同深度对照，不默认继续重跑raw。要迭代，优先针对确有原文反证的错误否定和阶段倒推，并完成收尾证据链核验；不能为了赢分放松上述标准。实验之外未更改全局Codex设置、未推进真实迁移、未push。
