# 文件级总结与停止依据：会员页一次验证

实施前登记。只跑既有 F10-01（0723 MemberCenterPage），Luna/high，一次独立调查，沿用原材料池和时间边界、同一句短任务、原始读取能力；不重跑原始组，不给模型旧报告或本次审查已知答案。1800秒上限，最多三次模型自行提交/审核，保留失败，不人工补稿。

## 改动和边界

- 同一 inquiry/1 扩展可选 summary、recommendations、finding.boundary；旧卡仍能按原稿加载，新技能交付要求这些字段。模型写总结，页面不另做摘要或扩大主张。
- summary 分生成解释、修复过程、未知，并关联 finding；recommendations 给优化对象、行动、理由、验证和对应 finding。单项建议可保留但不重复抄写。
- boundary 记录每个分支为何停止及对应节点。声明正确输入须指向 context，未查明保持 unresolved；脚本核格式、原文引用、连接与缺口，不认证输入充分、首因或建议有效。
- skill 把首次引入与沿用分开：查可见前态/实际收到的旧文件，出现相同问题就向其形成者继续追；确认关键输入正确可停，不要求固定链长，不强迫归责 skill。后继是否失职另查职责。
- 不改时间查询、原生效应索引或树的布局/连边算法。原生边、报告专属虚线边与模型主张边界不变。

## 判定

1. 工程：旧卡兼容、摘要假引用/未来引用拒绝、finding/node ID 不漂、缺失/未闭合停止依据不能成为 ready_for_review；不改原稿/轨迹，UI 全文可看且能回到对应分支。
2. 本次模型：仍按原会员页6个核心点核对，另核首次/沿用角色；不以树长或机检 valid 当正确率。不修改原 28 点标准。
3. 深度：是否真实复核前态；初始转换与后续接线的角色是否分清；关键输入正确或未知的停止理由是否有据，是否把尚未查明伪装成已找到根因。
4. 总结与建议：文件级总结不扩大节点原稿的确定性；优化建议能指出具体环节与验证方法，不仅罗列补丁或泛泛“加强测试”。
5. 本次只验证端到端可用和一个已知失败案例；无重复、不是盲测，不声称稳定准确率/泛化提升或 skill 单变量因果效果。
