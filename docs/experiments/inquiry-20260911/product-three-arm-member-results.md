## 结果：MCP 闭合了更多归因，但不是全面正确或降本

逐项原文坐标、等价解释和附加错误见 [三组语义裁决](product-pair-member-adjudication.md)。

成立要求已证明“相关正常输入实际交付 → 具体偏离输出 → 对应修复”；允许后继在正常输入边界保留错误的真实解释，不强迫每项唯一首次作者。原始散文与系统自动附证同等看待，不因原始组没树而扣语义分；但不能替任何模型补上它没有作出的关键归因。

这些是同一文件六类修改的**证明完成数**，不是六个文件的 ACC，也不是“原始组其余五条全错”。拆开看五类生成期问题：原始 0/5 成立、自由 1/5、MCP 2/5；第六项是返修新生错误，三组均正确区分，不掺入“首次生成作者准确率”。

- **原始组**：1 成立、5 部分、0 核心错误归责、0 遗漏。正确概括主要修复机制，但没有闭合生成期实际收件与具体输出的责任边界。不得因为报告没有固定坐标格式而降分；也不得把大致正确的修复解释自动算作已证明生成归因。
- **自由产品**：2 成立、1 部分、3 遗漏。图片和返修编译链成立；价格机制大致对，但未证明 S8 收到数字分段输入并在业务接线后写错。该稿没有像 MCP 组一样明确倒归价格给初始 converter，不能强行判同一个错误。其明确承认其它修改没有全部解释，因此 CTA/indicator/mask 记遗漏，不根据附证里“恰好有代码”代写结论。
- **MCP 调查产品**：3 成立、2 部分、1 错误归责。图片和 CTA 提供了可核的正常 XML 输入、生成偏离及修复；返修新生编译错误归给修复脚本。价格把 `item_product_info.xml` 两个控件的字号层级误当成同串数字/后缀的充分输入，并把错误挂到初始 converter：当时它只是数字占位，后缀实际由 S8 的 `showNowPrice` 接线引入。indicator/mask 找到修改，但相关生成期充分输入没有闭合；不能由评委替模型补 S8 的 Kotlin/宿主遮罩契约。

额外错误单列，不掩盖成立项：原始组说 CTA 动画/安全区“本身被确认正确”超过已有验证；自由组把生成者禁止编译与后来修复新引入的可见性错误联系过强，并有下文的标红和脚本前后态展示问题。三组都保留了编译通过不等于视觉复验通过的边界。

这说明本轮 MCP 产品在**归因证据闭合数量**上有收益，同时还有核心错归，且成本更高。不能据此称它整体零失误、大幅优于原始、具有泛化优势，或认定这些收益必然由机械校验单独造成。单文件单次，skill、调查接口、输出义务同时变化；原始组也有真实不足，但不是天然错误对照。

## 实际分组与隔离

| 组 | 给调查员的内容 | 实际调查方式 |
|---|---|---|
| 原始 | 简短任务、目标/池/生成结束/观察截止四字段；无 skill/MCP | 22 次 shell，全部读取独立目录中的任务或原始池 |
| 自由产品 | 同题 + 当前完整 skill/MCP/构树检查；允许原始读取 | 实际也选择 MCP：34 investigate、25 page、9 submit；4 次 shell 只加载指令/任务和执行审核脚本 |
| MCP 调查产品 | 同一产品，额外要求原始转录只经 MCP 查询 | 20 investigate、29 page、3 submit；2 次 shell 只加载指令/任务和执行审核脚本 |

因此，自由产品组**不是**“先纯原始调查，最后才检查”的实测样本；它和 MCP-only 都实际经 MCP 调查。两者单次差异不能证明限制入口本身有效。

原生 session、命令和全部实际读取均经审计：无 fork/resume 参数，无父历史记录；只有本轮任务及各组应有的指令。评审助手有开发历史，但不是被测调查员，没有向它们传递消息。自由组的一次上下文压缩属于本次长调查，不是 fork。

首次原始组误读原池父目录中的旧工具实验报告，**该次无效并保留**，不进入下表。随后把相同 290 个源文件复制到独立输入目录重测：逐文件名称/大小/SHA 相等，共 236,925,732 字节。输入父目录不放产品、旧报告或金标；第二句任务仅限定材料范围。新原始组的 22 次实际读取都没有越界。这里证明的是录制到的实际读取合规，不是操作系统强制禁止读取整个磁盘。

## 机械校验与交付

两产品最终都通过身份/时间/边的机械检查并可由卡片加载接口读取；本轮没有声称完成浏览器视觉验收。机械 `valid` 和 `ready_for_review` **不是语义正确认证**。

| 项目 | 自由产品 | MCP 调查产品 |
|---|---:|---:|
| 最终节点数（含自动目标） | 12 | 12 |
| 系统绑定关系数 | 16 | 20 |
| submit 调用次数 | 9 | 3 |
| 正确填写的 `problem:true` 节点 | **0** | 3 |
| 可定位但仍待语义审阅 | 是 | 是 |

实际拦截不是假设：自由组先后被拒绝错误路径、非法文件间关系、错误节点序号及未来证据，9 次提交后通过；MCP 组第二稿的读取证据晚于文件端点，被拒绝，第三稿去掉该晚时证据后通过。详见 `reviewer-only/member-submit-mechanics.json`。这些证明检查纠正了提交关系/坐标，但不证明价格等语义误归自动被纠正。

自由产品稿在三个 `reason` 里写了 `problem:true` 文字，却未提交该布尔字段；最终编译结果为 11 个 context + 1 个目标 repaired。**问题指控不会按预期标红**，不替模型手工修复，不将“可加载”报成展示目标已经达成。当前可选字段与检查反馈未发现这种交付不一致，是明确产品缺口。

自由稿还把价格脚本写完的 `file@21:30:20.292` 用作该脚本的读取输入节点。普通“截至此时有相关调用”与“读到的是此节点的写后内容”不是同一件事；其 force 边通过不等于读入状态已证。这属于端点/状态表达的残留风险，不能因机械 valid 就把后态当成先前输入。

两组均仍有 41 条未逐一裁定的调用；这不是 41 个漏掉的真实修复，但也不能宣称全修改完备。MCP 组送出的 139 个帧、自由组 199 个帧均在原生录制中匹配，宿主截断为 0；未主动展开的正文不等于工具丢失原文。

## 实现与复现限制

本轮只扩展既有实验启动器/冻结检查及测试，未改调查产品 skill、内核或 UI。相关回归全量 3401 通过、10 跳过；这只认证测试断言，不认证模型归因。

现有 `prepare-product-pair` 仍引用基准原池位置；fresh 工作区本身不能阻止模型枚举池的父目录。有效 raw-v2 用独立复制池并复用同一 `RAW.launch` 启动/录制，单独封存 `isolation-manifest.json` 与 `input-integrity.json`。再次复现必须同样独立布置输入并审查实际读取，不能只重跑旧 prepare 命令就声称已无污染。通用隔离准备尚待收进启动器。
