# 已有结论的证据树复核

这是调查后的独立收尾阶段。先读 `initial-report.md` 和 `investigation.json`，再完整读 [MCP 调用与坐标模板](references/mcp.md)。前稿是待复核的模型判断，不是参考答案。原始材料池不变；可自由用原始读取和 MCP 补查，不执行历史命令、不联网、不读其它实验答案或当前工程、不委托其它模型。

## 保留解释，核必要条件

将原稿中实际修改、原因、阶段边界、未知与建议保留在卡片 summary / recommendations；可精简措辞、合并原因，但不能只留下方便连线的部分。节点 reason 说明它对哪个问题起什么作用，普通边只声明真实文件/agent与时间坐标，具体字段见模板。

- 对每个用来停止上溯的输入，核原文中与该具体问题有关的要求：要求什么、何时实际交付、输出如何符合或偏离，为什么足够适用。文件名、摘要、“读过”、通用知识都不能代替具体约束。关键输入各自入树；一项充分不代表其它项充分。
- 输入正确充分且输出仍偏离，可以停在该环节；不必再追正常输入的作者。输入有遗漏/矛盾且形成记录可查时继续查；未记录形成过程可停止并明确证据边界。没查完不等于没有记录，未知不等于正常。
- 核问题内容的实际交接：写者 → 被后继读到的中间文件 → 后继写回 → 后续状态 → 目标。多时点可以重复同一文件；有实际传播证据才连，不为长度补边。独立修改可并列，原文不足就保留缺口。
- problem:true 只标有具体错误依据的节点；正常修复、不确定效果或仅参与流程都不够。后置标准不能直接当作生成者当时违反的要求。

## 机械反馈如何影响结论

第一次不填 force；读完全部校验反馈，先修身份/时间/格式。有原始调用支持但解析器未确认的边，按模板复核后才能 force，保留虚线。没有边不是语义反证，连上边也不证明节点原因正确。

只有发现具体原始反证或新证据才修改因果判断。在 summary 末尾写“复核变更”：原判断 → 新证据 → 保留/补充/降级/撤回及理由；若只是坐标或表达变化，也明确说明。不得为了拿到通过状态删除困难主张、正常输入或未闭合分支。无法接通时交 draft，并保留具体缺口。

用 submit 保存原稿，按模板运行 scripts/check_card.py 审核。长反馈必须续读完。到时间预算或连续两次无实质进展时停下，交最后原稿的 report_id / source_sha256 / 状态。原稿文件由运行器冻结，不能改写 initial-report.md。归因正确、输入充分和优化有效不由机械通过自动认证。
