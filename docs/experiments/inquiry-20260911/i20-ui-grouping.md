# 同一坐标的多条结论，合框展示但不混成一个判定

真实 i20 会员页价格链中，原稿 A:origin 与 A:source 指向完全相同的 Slice8 agent 时间范围，但分别承载输出归因和输入背景。原有读边接后者、写边从前者出发，画成两个独立框后看似两条断链。

本次仅改变 page.html 的显示投影：

- 仅对已核实、同 finding / kind / 完整 key / at / since 的坐标合框；字符串精确比较时间，不用 Date.parse 丢失微秒；未核节点、不同上下界或不同路径不合并。
- 框内每条原稿记录有独立角色、颜色和点击入口。点击背景不显示成问题原因；点击整个框可并列看所有原稿理由、证据、时间核验及执行者告警。
- 不添加任意边。每一条已有边保留，指向实际成员行；内部边/自环保留为弯线，candidate 仍虚线。合框不是证明 agent 如何思考或推导因果。
- 不改 YAML、存储 graph、MCP、查询、报告验证或模型轨迹。修复者 Bash 效应尚无原生可核关系时仍可断开，不能为漂亮强接。

验证：170 项 inquiry 回归通过。增加纯显示函数测试覆盖混合角色、不同 since、微秒差异、不同 finding/路径/别名、未知节点不合并、内部边/自环、无原始边不生成边、输入不可变。真实浏览器检查每个成员点击时的原理由和全部 evidence；另用明确标为 synthetic_display_only 的内存夹具验证合框后两条既有内部/自环边均可见、虚线数量不变，无提交或持久修改。
