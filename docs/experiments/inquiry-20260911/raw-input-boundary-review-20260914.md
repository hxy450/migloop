## 应如何使用这次复审

1. 不改旧25/28与27/28；它们仍是原先定义的核心解释覆盖，不是完整产品验收。
2. 对两组同样增加“问题相关的历史输入边界”审阅：实际条款、发生时刻、接收者、输出偏离或明确后置需求、传播到目标的依据、未知边界。允许散文给等价证据，不能要求原始组事后满足未分配的YAML格式。
3. 区分三种结果：输入充分且实际收到仍偏离；输入确有缺口需继续追；记录本身不可追溯则有界停止。不能把“查询没命中”当作“历史没有”，也不能把“读过文件”当作“输入充分”。
4. 工具组同样审。机械边通过只证明关系，不认证reason、输入充分性或内容传播。本次两阶段Dice即存在原因晚于节点截止的问题，不能因原始组有问题就豁免它。
5. 优先离线复审现有产物，不重跑原始组、不扩题、不用强模型代写后拿来报调查员成绩。再针对查实的缺口改工具或skill。

这次更准确的判断是：**用户质疑成立在“高分不代表输入边界完成”；不成立在“原始组必然找不到正确边界”。我们的评分与对外表述需要对齐完整产品目标，而不是把局部正确说成归因已经做完。**
