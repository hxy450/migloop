## 由实际失败驱动的变更

i09-high Splash 引用了修复者同一条 Bash 请求（L346 / e-4416f25f78c5），但只展开 onWillDismiss 字面窗口。该命令后半段实际还修改 Progress 的 strokeWidth/enableScanEffect；报告却称没有相应进度条修改。这不是收集器遗漏该调用，也不是模型没有权限读它，而是部分展开被当成了整次修改的覆盖。

- 未证明只读的 Bash/exec_command、Edit/MultiEdit/patch 等请求保留完整选定参数，关键词不再裁掉同包的其它修改，并标记 `whole_argument_packet`。仍尊重显式 JSON pointer。结果、源码和规格仍可按词窗口读取。
- 不由此认定脚本执行成功，不推断脚本作者/读写边。未决效应仍需证据。
- 多关键词一次 casefold；agent 直接以 source 索引限域，file 先构造稀疏关联 ref 并集，再匹配正文。此前查询计划对无关转录也反复做全文匹配。

真实池三个查询的完整 JSON 摘要逐一相同，单次局部测量：全池三词 3.034→1.633 秒，文件相关调用 1.201→0.041 秒，agent 三词 4.456→0.028 秒。缓存/负载未受控；不算模型端到端收益。复现脚本为 `bench_search.py`。

105项独立内核回归通过，包含 Unicode/字面搜索、其它 agent/文件正文不参与匹配、复合请求不藏第二处修改、显式 pointer 和原生关系不变。旧默认入口不动。
