# tools-v4：冻结前登记

2026-09-10。沿用原始组、tools-v1/v2/v3的全部产物和冻结评分核心；不重跑原始组，也不挑选有利重复。本轮直接跑十文件各两次，不另做有选择性的pilot。新跨运行队列尚未构建归因参考，也未启动模型。

## 候选范围

- 请求内按源复用原始解析，128MiB条目记账预算、无驱逐、结束释放；每次查询重新应用时间、源所有者和目标范围。不保留整个池的事件投影，不把缓存命中当证据。
- 短原始任务消息最多展示4096字符，仍受交付预算裁剪；超过的保留原文指针、总长和续读入口。没有摘要改写或个案检索词。
- 版本化、可逆的外层batch压缩，仅省可以由实际正文与原请求精确还原的重复字段。新回执核实际wire、原请求及canonical数据；旧回执保留。`max_chars`仍为data预算，不是整个工具返回或token硬上限。
- `via.trace_identity`与实际轨迹使用相同的安全单键result包装解码。调查顺序不成为历史读写边。

运行器为新建 `file-first-10/run_tools10_wire.py`；旧raw、tools、overview运行器及原生解析器不改。新适配器只处理冻结包的wire smoke与自身绑定，模型、任务前缀、队列、失败规则与后处理保持不变。runtime snapshot包括用户现有service/deveco工作区字节，实际身份以code manifest为准，而非仅Git提交。

## 已观察到的离线结果及限制

按同一快照开关请求缓存，24项查询90.59976→23.76548秒；选中和裁剪后的数据完全相同，仍为4项ok、20项deferred，没有以性能改善冒充更多证据已交付。一个先前的整池缓存实现因超预算未命中且变慢，失败记录保留。

同批完整返回90946→80335字符，下降11.67%；编解码增加约毫秒级CPU。字符不是token，单次离线处理不是模型端到端耗时，未据此宣布新版本胜出。

独立接口审计174 passed、2原可选browser skip；另有请求缓存、字段原文与冻结runner测试。最终全套复跑第一次使用默认系统pytest目录失败：`WinError 5`拒绝访问`AppData/Local/Temp/pytest-of-hongy`，837 passed、2 skipped、1649 setup errors（39.64秒）。未修改目录权限或删除临时目录；改用项目评测区内经过校验、此前不存在的独立basetemp复跑。该环境失败不删除，也不当成运行时回归。

## 本轮判定

同一Luna medium、2重复、2并发、1800秒；不回退模型、不自动重试、不补格式修复轮。全量保留报告、实际调用/返回、token与失败。正确性按原冻结核心判定，格式审计独立，不因YAML合法或引用有效给因果分。

只有文件等权核心覆盖、主张准确性、整文件通过不退步、重大错误不增加，才可称质量非退步。实际token、非缓存输入、investigator及含后处理耗时分别列出。此开发集已经反复使用，任何获胜都不是新业务泛化证明。

新dynamic1六文件与arch11七文件的边界/曝光另行登记；实现冻结后才建立并独立复核有界参考，参考冻结后再跑新原始/工具双组。跨运行结论分队列报告，不合并旧十文件分母，不将同app或曾曝光页面族改称未见业务。
