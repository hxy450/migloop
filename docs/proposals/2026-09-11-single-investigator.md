# 一个调查员，自由查阅，提交时生成证据树

## 用户裁定

保留原始读取能力；同一个模型完成调查、判断、补证和结论提交。调查可以跳跃，不要求 via 或沿图走。**正式提交必须调用工具，将自己的结论绑定为可复查的文件/agent 证据树**。不再由第二个模型重述或判定第一份报告。

这里的树是模型提交的解释链，不是模型脑中的推理，也不冒充实际查阅顺序。历史关系可以是有共享节点的图，页面按树展开；没有依据的关系保留断点，不能为了漂亮而补边。

## 以前的问题，按底层责任归并

| 问题 | 实际后果与现状 | 底层约束/处理 |
|---|---|---|
| 解析推断冒充事实 | 早期唯一目录候选升作者、未知 Edit 后快照封到旧版、条件 shell 写入等已修；仍不能把解析结果当全体历史事实 | 原始事件是底座，操作/执行/内容/作者/原因分开。候选不升事实，未识别也不等于没发生 |
| 时间与版本混用 | 后修读回被当生成输入、末次作者被当首次引入者；时间接口已存在，但时间本身不是因果证据 | 所有原文、搜索、修改共用时间范围；发起与完成分开；不透明窗口保持未知，不伪造快照 |
| 材料可查但默认看不见 | 会员页生成截止概览只交付最初写入，Slice8 等后续作者藏在分页/正文入口中 | 概览给全范围的紧凑参与者目录，操作正文继续分页。目录不靠最早几条样本代表全体 |
| 原始查阅与工具坐标脱节 | shell 找到 source:line 后，还需绕 index/search 获取 raw 引用、猜 agent 身份 | 统一原始地址转换：只在登记源内按源名/路径+行定位，返回内容指纹和展开结果；不依赖读写解析 |
| 查询路线、历史关系、解释链混用 | via 约束调查；后来取消约束又容易将结论节点误画成查过的节点 | 实际调用由记录器保存；历史边核原始依据；节点原因由模型提交。三者独立叠加，不合成不存在的路线 |
| 机械标签被当语义裁判 | 后置模型把 candidate 当成原始价格/图片修复不存在；引用正确仍可能引用错内容 | 主张原样保留；定位、关系识别与语义支持分别标。工具未认证只能产生待核状态，不能替模型撤销结论 |
| 提交可绕过工具、重复抄长 YAML | v3 guide 明确允许不 check；报告与检查稿可能不同 | 单调查员工作流必须 check 后提交对应哈希引用；工具生成图，保留未证边与诊断；不要求所有诊断清零 |
| UI/MCP 漂移 | 时间界面切换漏接旧派发，手动探索/展示回退；派发已补接，不代表所有交互已验收 | 使用同一查询与论证构建器。现有页面小范围接线，不再换一套 UI；API 和浏览器验收分开 |
| token 少但慢 | 多次小展开、重复 JSON/来源扫描、强制格式往返，省了信息却未省延迟 | 已有批量/显式全文展开继续保留；索引与正文分离，避免重复提交长稿；不以截掉关键输入换 token |
| “找全”、归因正确与机制解释混分 | schema/引用通过被误读为归因正确；局部错误被扩写为无证据 skill 故事 | 修改关联对账、原文事实、局部归因、机制假设分别验收；未知效应不是缺陷数，优化建议不是已证根因 |

不是把这些已修复的历史 bug 再报成当前开放缺陷。当前重点是默认披露、原始读取接入、提交闭环和证据语义边界。

## 本次实施边界

1. `record` 共享底层支持登记源 `source + line` 定位；MCP、batch、HTTP 共用同一范围校验。未知工具的原文也能绑定，歧义/池外/时间越界失败，不猜旧引用。
2. 文件概览从完整操作组生成参与者目录，区分确认读/写与候选调用，列各自范围和导航；不从前几条操作抽样、不凭目录立作者边。
3. `check` 返回该稿的呈现摘要和可复制提交引用。同一模型收到诊断后可自由补查、改稿、重查；最终引用必须绑定本 run 的完整真实调用和原稿哈希。
4. guide 将调查自由与提交责任分开；明确没有机器认证不等于反证。复用 v3 数据模型与既有 UI，不增加“模型必须找到多少跳/必须归罪 skill”的门槛。

## 验收与未达成项

回归首先覆盖：源名歧义/池外/改行指纹/时间截断、未知工具原文；概览晚期参与者不消失；same-run check 引用、改稿后旧引用失败、只有 shell 查阅也能提交；未确认边不删除模型原因、不补成实线。

代码和机械验收不等于归因准确率。后续仍用同题 Luna 与冻结 raw 对照：调查与提交由同一原生会话完成，成本包含提交阶段；工具不见参考答案。分别报告局部正确覆盖、机制证据、展示保真和成本，不以连通图或长链奖励模型。

尚未解决：长尾脚本语义、未记录/丢失上下文、历史无快照的精确状态，以及“改 skill 是否真的降低下一次返修”的干预验证。不得声称本次底层改动保证完整性或正确性。

## 第一批实施结果

上述四项已实现，旧报告兼容保留。新 `submission.load_checked_submission` 独立于旧报告加载策略，要求同 run 的显式 check 引用，不能从没提交的草稿或散文兜底猜稿。允许保留诊断，来源绑定成功仍不等于结论通过验收。

真实单模型试验已完成，原稿按字节物化到 YAML，浏览器验证了节点原因、参与者目录和独立跳转不篡改模型轨迹。归因仍2/6，固定 raw 3/6；不能宣布正确性改善。模型已开始查询 Slice8，但没有完成其输入/输出对照。

运行后又据剖析合并了全局与请求缓存的重复内存计权，并补上无效边引用的专门诊断。没有扩大缓存上限、篡改原稿或补造历史边。详见 [本轮实测与验收](../experiments/longchain-20260911/single-results.md)。
