## 已落地

1. **条件效应贯穿收集与重建。** 移除“cd/mkdir/echo 几乎不会失败”的白名单。完整、简单 AND 链的成功返回才允许推导链内执行；后续独立语句、OR、管道不能用总返回码给先前分支背书。heredoc 继承所属命令的条件性；不支持的控制结构回退候选。条件读不靠通用 stdout 升级为已见输入：`false && cat A; echo b` 的 `b` 不是读到 A 的证据。CC 和 Codex 的 shell 收集均过滤这些候选。
2. **候选写是状态屏障，不是修改版本。** `conditional` / 方向不明 / 失败或未完成写的具体路径，在构建编年史之前进入引擎，阻断向前封口。调用有结束时刻时，两端均设置屏障。之后的 Read 可以提供新观察，但不能把内容封到更早的未知写者身上，也不能据此声称发生了“实录外修改”。候选前后内容相同不制造假修复；跨屏障 diff/行归属保留未知或 bridged 标签。
3. **脚本历史只有一个写者。** CC 全池（包括前序根会话）统一预扫描，正式收集只读。Edit/MultiEdit 顺序应用一次，尊重 replace_all；正文在完成时刻才可用。未知覆盖、删除、失败、未完成、重叠写产生未知墓碑。按规范化时间查询，不借别的路径下唯一同名脚本。没有新增真实 shell 重放。
4. **引用不再猜补身份。** 块号取原始 content 数组下标，混合 thinking/text/tool_use 不碰撞；多动作同行必须带块号，包括 `/0`。缺块号不能解释成另一调用的动作号漂移；无转录标识即 `untagged`，不再报强 `ok`。无 tool_use_id 的稳定身份包含行号与原始块号。cite_check 按 JSON 中实际 `type=tool_use` 块收 id，不认普通 metadata.id。
5. **扫描缺口进入实际查询响应。** 命令、脚本正文、输出、说/想、收件、派发词、消息、Write/Edit/MultiEdit 输入统一记录预算缺口。预算单位是字符（2,000,000），不是字节；另有每次扫描 2,000 个不同词法提及上限。index/file/agent/search/action 披露缺口；`index(kind=scan)` 列原文指针，`action(part=input|output, offset=…, find=…)` 可分别翻页，长 Write 输入不会永久卡在前缀。

没有把候选升级成作者，没有替模型自动归因，也没有新增知识图谱数据库。

## 明确的代价与未完成事项

**读集合变保守是实际代价。** 1,024 条动作含条件读候选，不等于 1,024 条原读记录被删除，也不等于它们没有执行。部分普通 `cd && grep … | head` 也会退候选，因为目前未建立足够严格的管道输出来源证明。原文和候选导航保留，但模型可能需要更多展开。下一轮必须同时量报告遗漏、错误归因、工具调用数和输入 token，不能只看引用有效率。

本批没有解决完整 shell/Python 语义、任意动态脚本的副作用、所有已确认调用的共享工作区并发归属、全局时钟/因果顺序、源头快照，也没有证明修复版本已找全。跨根会话脚本历史这次接通的是 CC；Codex 复用条件效应规则与完成时刻，尚不是与 CC 等价的全池脚本历史重建。

建议后续只做一次冻结版本的固定任务对照：同模型、同任务正文、同预算、同原始数据池，工具组与原始组比较；报告以稳定事件和版本清单机械核验。候选导航是否增加成本应作为主要指标之一。旧 `cases_tools5` / 正在运行的其他代码版本产物不能算作本批验证。

当前结论：本批已修复并锁住验收集中复现的证据污染，具备继续实验的底座；**尚未证明工具报告优于原始转录，也尚未得到全量修复归因完备证明。**
