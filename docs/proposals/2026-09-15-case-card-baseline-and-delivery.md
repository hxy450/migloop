## 用户本轮确认的目标

- 最终需要一张有总结、建议、节点原因及证据关系的情景卡，并能在对应迁移的返修页载入、复查。
- 不要求为了展示，让调查员额外承担无必要的整树编排、坐标维护与反复重写。
- 借鉴 i14 的调查和证据组织方式；将 i14 作为历史效果基准，与已完成的同模型原始 high 实验作回顾性对照。
- 汇报同时介绍最新情景卡与 UI 能力。实验版本与展示版本分别注明，不能把历史结果包装成最新版已复测结果。
- 主报告聚焦用户价值和可核正例。开发故障、失败探索和后续修复清单放在内部记录，不堆到主展示面。

本轮仅记录决定、核实来源并编写汇报材料；未回滚代码、改模型原稿、修改历史评分、启动新实验、提交或推送。

## 后续具体改了什么

下表是可定位的实施差异，不是已经证明的退化原因。提交名是定位入口；冻结代码和原稿是最终依据。

| 改动 | 代码/提交证据 | 实际变化 | 待验证的风险 |
|---|---|---|---|
| 调查说明移成 skill，增加交付审核脚本 | `6f593a1` | 从内置GUIDE＋任务，发展为skill读取、提交、调用check_card、交付回执 | 指令和交付步骤变化可能改变注意分配；不能断言skill本身导致退步 |
| 文件级总结与建议 | `156c11a` | 在已有逐项finding之外增加整体叙述 | 总结有用，但不得覆盖逐问题的不同责任与输入边界 |
| 声明路径及回执检查 | `c668bd3` | 增强实际交接、时间与检查回执核验 | 交接证据的正确性提升，与原因语义正确性不是同一件事 |
| 首次普通提交、后续force | `1e39006` | force与先前检查、具体坐标绑定；附实际调用证据 | 反复调时间和重提可能挤占查证；不能为减少次数取消真实关系核验 |
| 精简坐标卡 | `e9eaa7e`；当前`card.py:102,211` | 模型交`target/summary/recommendations/nodes/edges`；多个问题口述进同一节点reason，内部编译成一个finding | 单字段减少，但逐问题证据分组消失；不同缺陷的充分输入与责任可能被混同 |
| 关键输入分支必须显式入树 | `70724c7` | 不允许只在reason提到skill/spec而不声明输入分支 | 用户目标有价值；“查明原因”与“补齐展示坐标”的负担需要拆开 |
| 中间文件状态与传播必须显式连接 | `de174f8` | 强调早期写者→文件@读完→后继@写完→下一文件状态；明确problem标记 | 不能把存在读写链当作同一问题连续传播；也不能让连树成为调查的优化目标 |
| 返回、分页、搜索和路径解析变化 | `b8dc835`、`ea9f6a8`、`1d643fc`、`a394f4b`、`0f5695a`、`f734648` | 修可见性、展示顺序、候选入口和误解析等 | 同期有真实底层修复，不能把所有后续提交都当坏改动回滚 |

i14原稿按finding分别保存 `reason / changes / nodes(scope, role, reason, evidence) / unknown / recommendation`。GUIDE建议不手填edges；`evidence_graph.attach()`只从已引用原生读写补确定关系与中性端点，不自动认证脚本或因果。

当前精简卡的字段更少，却要求模型同时维持统一节点表、跨时间边和多类原因。是否导致推理与成本退化，需要单变量验证；目前没有证据把回退归因给某一个提交。

## 已观察到的回退与收益，分开记录

- 价格归责：i14会员页原稿D明确区分converter数字占位与Slice8接入含后缀业务数据；当前会员页MCP原稿把该缺陷前移给converter。这是具体语义回退，不只是评分变严格。
- 跨轮成本：同F10-01/02/03三文件，i14为16,680,735 token、1,850.766198900062秒；当前三文件MCP为23,807,679 token、约2,899.13秒，分别多42.7%、56.6%。非同期、任务/协议等多因素变化，不是消融结论。
- 不是所有文件都变慢：会员页i14为836.66秒、当前为623.83秒；两者都是3次submit。不能说“i14因为不用修稿而更快”。
- 当前反馈确实修过身份、越界时间与中间状态坐标；两轮新case-card试验的核心归因完成数未净增。机械收益与语义收益应分别记录。

## 产品约束：需要情景卡，不需要模型手工承担全部展示编排

保留：自由调查；原始材料可追溯；file/agent＋时间；按问题保留原因与建议；可保存、可载入；已确认关系和模型复核虚线分开；当前手动探索、总结/建议和冻结交互。

下一候选应优先评估：

1. 保留 i14 的逐问题证据组织，避免为了少字段把所有问题混为一个全局原因。前台仍是一张文件情景卡，内部可以有多个finding。
2. 坐标、确定读写关系和原文引用尽量复用服务器已返回信息；模型负责判断、选择证据及真正未解析关系的解释。
3. 图装配是确定性投影，不为了展示改写模型原因、添加未知因果或强制无限上溯。
4. 机械错误反馈关联受影响的原因；能复用原证据就复用，避免整稿无关改写。一般身份/回执可由程序传递，不要求模型抄SHA。
5. 保留不完整/未知状态；可保存、可载入与归因已证分别表示。

这些是记录的方向，尚未实施。没有删除当前内核、UI或冻结实验，也没有构建并行第二套生产实现。
