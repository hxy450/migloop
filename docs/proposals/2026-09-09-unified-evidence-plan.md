# 从静态契约到历史案例验证

本轮基线：`6ffb74c`，`dev/fixchain`。优先顺序：归因正确性与可审计性；其次是 token / 时间。没有重跑真实迁移，不把历史解释当成已验证的管线优化。

## 一条清楚的数据流

```text
原始事件 → 收集证据/候选/纯提及 → 两原子账本
                                   ↓
                           共用 atom_queries 查询
                             ↙                ↘
                         MCP 文本           HTTP JSON/文本
                             ↓                ↓
                      真实调用/返回轨迹 → 调查时间线
                             ↓                ↓
                         原始模型 YAML → 机械核验 → 节点原因、文件事项
```

不增加第三种原子。事实图与调查路径不是同一张图：前者表达文件和 agent 的读写依据，后者表达调查员确实查询过什么。搜索发现的新线索可以独立打开，不能为布局便利虚构一个读写父节点。

## 本轮边界

1. **事实准入**：方向/目标、执行证据、内容是否交付、快照完整性、版本绑定分别记录。单凭脚本中有路径与 write 关键字不立正式写入；exists 不算正文读取；纯提及不能打断内容状态。超出有限语义支持集保留候选与原文，不继续猜执行。
2. **统一查询**：`atom_queries` 负责参数规范化、原子选择、时间截止、版本窗口与两种投影；MCP 只额外负责打开节点的状态和搜索凭据。JSON 与文本不承诺字节相同，文本有展示预算，但作用域、显式布尔参数和时间截止不能各解释一次。
3. **分层展示**：时间线保存所有查询、失败、重复访问、搜索与声明 via。主图只投影已录转移中、有真实端点和原始操作依据的读写边，方向按因果方向而非调查方向；不声称投影是所有可存在的账本边。
4. **省略可见**：大 agent 的 reads 缺省可折叠，显式 True 必须能展开；窄窗口另给早期输入计数和有限索引，不把省略误说成不存在。元数据不自动证明输入与当前缺陷相关。
5. **结构化交付**：作者格式继续严格 `migloop-verdict/1`。每条缺陷的修复锚点、进入点、节点角色/原因/证据/依据保留。UI/归档增加系统投影 `migloop-findings/1`：按模型声明且可定位的修复文件归集同一 item 的引用；无锚点的保留为未绑定条目，不偷用 root 补归属。
6. **提交不抄第二遍**：实验性 `migloop-verdict-ref/1` 显式引用本次最后一次真实 check 的原始草稿与规范化文档双哈希。源调用、返回或身份缺失时失败，不捞旧稿；needs_review 保留诊断。原始 YAML 与系统投影分别保存。

## 不应宣称的能力

- 引用有效、basis 齐全、哈希一致都不等于原因正确。
- 两原子不是所有系统调用的完整追踪；候选未获证实不等于未发生，原始转录本身也可能不完整。
- 文件桶证明坐标存在，不证明模型说的修复目的或因果关系。
- 旧报告必须按旧账本身份阅读；解析能力变化不能把同号版本默默重新绑定。
- 模型写的“建议”与已经实施的 repair 不同。当前 v1 未提供推荐字段就保留 null，不从 notes 猜出建议。

## 验收顺序

1. 合成反例：CC/Codex 同源准入；条件/失败/提前退出/名称遮蔽/纯提及/元数据探测；真实阳性仍可用。
2. 查询契约：MCP/HTTP 文本同体、显式 False/0、别名冲突、未知参数、窄窗口与 until 完成时间不串线。
3. 归档与 UI：错误身份/伪造引用/缺失结果/损坏最后提交不得成功；原文逐字保留；图不画搜索、提及和布局假边；原因按缺陷×节点×版本展示。
4. 历史真实回放与模型实验：保存源提交、pool/task 哈希、实际模型、所有成功失败产物，不覆盖旧跑。

## 下一项预注册开发实验

目的仅检验“最终引用已核草稿”能否减少重复交付成本而不损失载入与审计，不把新解析器、查询窗口或 UI 改动的收益混算进来。

- 案例：已冻结的 MemberCenter（S3/S4）和 Codex C4；均来自 attribution10，明确是已见开发回归，不是 holdout。
- 两组使用同一新冻结代码、同一原始 pool/common task、GPT-5.5 medium、native MCP、相同超时与工具白名单。唯一可控差异是最终 document / reference 模式及必需的提交说明。
- 每案每组两次，共八跑；两轮交替起跑顺序，不挑最佳一次。单次失败保留并计入载入率，不静默覆盖或只报成功。
- 质量硬门：显式提交与最后实际 check 绑定；UI 展示原因/证据和保存原文相符；无跨 run 恢复、假身份、假读写边。独立按原始证据逐项检查因果责任、时间义务与验证边界。
- 成本：output、input_total、cache_read、uncached_input、端到端 wall；另列最终回复字符、draft 输入字符、工具返回字符、调用数、重试和成功载入率。input_total 已含 cache，不再次相加；美元不可得就保持未知。
- 判定：任何静默误绑/虚构成功即失败。先报告每次语义与载入情况，再比较配对成本；两次重复仅用于发现不稳定，不能支撑总体显著性结论。总成本受路线变化影响，不能全归因于少抄一遍 YAML。

后续若成本下降而语义不退，才考虑让模型只填 manifest item 的判断，省掉确定性坐标抄写；不在本次混改作者 schema。

## 冻结前验收结果

- 完整 Python 回归：1,206 passed（17.84s）；浏览器：114 项功能断言通过、无浏览器异常。截图在外部实验根 `ui/static-contract-main-01/`，没有覆盖旧图。
- HTTP/MCP 共用规范化与文本实现；JSON 是明确独立的结构投影。JSON 不支持的 `start/n/part/offset` 等展示参数明确拒绝，不再默默忽略并返回全文；JSON blame 的 changed 已统一生效。
- 旧保存稿的 data 必须与 raw 一致；不一致不落问题染色。完整历史 schema 修复稿可保留，但另标未认证保存来源；不会标成实际最终回复。正文来源与原因语义两种验证仍独立。
- 两个真实池只读建账已通过。新准入主动将不能证明的旧版本/读取退为候选，因此旧同号版本不得继续使用；C4 当前只保留一个未复原全文的真实 patch 版本，之前 JS 循环读的原文仍可调查。这是召回代价，不宣称已经提高模型准确率。
- 尚无本轮新模型结果；八跑对照按前述方案执行，版本冻结后不在原跑上修改源码或提示词。
