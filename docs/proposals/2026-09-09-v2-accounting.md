# 两原子调查：v2 有限清单对账与忠实展示

保留 file@版本 / agent@版本两种实体。候选动作、查询访问、结构化主张是附属记录，不作为新知识原子。图上路线来自原始调用及 `via`，不是根据报告补出来的因果链；每个节点的原因仍是可质疑的模型主张。

## 本批实现

- 原始 sessions 返回与 harness 独立核账本身份。冲突时阻止当前版本绑定，包括没有 via 的旧报告；不能由模型在 YAML 中填当前身份覆盖旧查询的身份。
- 正式产出允许 notes 字符串或字符串列表，保持坐标、引用、边的严格校验。旧块重新校验单独记录，不修改历史产物。
- `sessions(file=...)` 给出有限分母：返修链每个记录版本，以及同链参与者窗口内、可定位到精确目标的未确认触碰/提及。跨来源按事件身份和目标去重；不会将唯一候选升为作者。
- YAML `coverage` 每行只能指向 `node` 或 `candidate`，说明 explained / unresolved / not_repair、关联事项、理由和证据。区间端点不替中间版本作答；每个未交代项单独列出。
- 页面并列展示查询次数、访问记录、实际绘制实体、模型结论与清单登记情况。用户自己打开清单项不增加模型“查过”计数。候选不自动染红或制造版本；身份不匹配时保留历史诊断。
- action 默认只展开原文与确定关系，可能涉及的文件先给计数和翻页入口；显式展开可恢复全部分页。原文窗口未压缩或更换成摘要。
- 相同观测端点只能证明端点文本相同，不证明期间没修改；未知内容的差分数量不能伪装成 0。
- Claude 与 Codex 收集路径均保留“部分效应已解析、仍有脚本执行未知”的双重状态，不因已写出脚本文件就隐藏后续动态执行。

## 不声称已解决的事

清单完整不等于现实修复完整，更不等于理由正确。当前候选受已知目标、同链参与者和采集预算限制；一个版本内可能有多个语义修改。全部登记 unresolved 可以完成结构对账，但不能通过质量验收。引用能定位不等于支持原因；成功构建不等于设备功能验证。

真实 Splash 案例为 9 个记录版本、15 个候选，其中图片尺寸和遮罩两项真实修复只在候选层，不在正式版本层。这个数是待交代项数，不是缺陷数。此前工具报告漏掉它们，所以优化重点是给调查一个可核分母，而不是要求模型写更长的链。
