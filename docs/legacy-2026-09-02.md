## 2. 和 dev/fixchain 的行为差异(调查时要知道)

- `sessions` 一次回全部链,没有 `file=` 过滤;`blame` 只有整文件模式;`agent` 没有 `since` 窗口(主会话整个生命周期一次给出,几十万字符)。
- 链只认 `.ets`;修复方按血缘层的 agent 级阶段判(主会话在 verify 阶段亲手改的不算修复);没有 execute 结束时刻的切分;没有 created / template 链根。
- 派发边按派发词开头对齐,并行派发时名片可能配错;脚本字面量的倾向兜底没有上限,0723 会多出假链(当时 31 条,主干修完是 19 条)。
- 没有 T+ 相对时刻、没有 build_evidence、审计不吃账本链。
- 两原子只支持 Claude Code 会话;codex 会话报错。

## 4. 怎么跑

```bash
# 依赖:Python ≥ 3.9;MCP 需要 mcp 包
pip install -e ".[mcp]"          # 或 PYTHONPATH=src

# 本机服务(报告页 + 链页 + 两原子 HTTP 文本端点)
migloop <会话 id 前缀|jsonl 路径> --serve --open
#   GET /api/insight1/atom/<sid>/text/<tool>   tool ∈ guide|sessions|index|file|agent|blame|diff|action

# MCP(stdio)
python -m migloop.mcp_server
claude mcp add migloop -- python -m migloop.mcp_server
```

技能 `docs/skills/migloop-investigate/SKILL.md` 里的 `BASE` 写的是当时 hmigbot 的 18601 端口;用 `migloop --serve` 时换成它打印的端口。

复现那次实验最接近的做法:主干 `docs/experiments/2026-09-03-per-chain/prompt_template.md` 就是这套七步路径的 `claude -p` 版(给链坐标、纯工具),`harness/run_probe.py --template prompt_template.md --chains AboutUsPage.ets`,MCP 配置指向本分支的 `src`。原始实验是会话内子 agent 走 HTTP 端点,不是 `claude -p`。
